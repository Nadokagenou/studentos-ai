## 17 พฤศจิกายน 2569 · รีดีไซน์ R3: แท็บงาน = รายการเดียวแบ่งตามเวลา (คง 0A0)

- หัวจอ "งานทั้งหมด" (ค้างกี่งาน · เสร็จวันนี้กี่งาน) · ช่องค้นหา · กลุ่ม **เลยกำหนด → วันนี้ → พรุ่งนี้ → 7 วันนี้ → หลังจากนั้น → ไม่มีกำหนดส่ง → เสร็จวันนี้**
- ตัดออก: ตัวเลือกมุมมอง วันนี้/สัปดาห์/รายการ · การ์ด "ควรทำก่อน" ที่ซ้ำกับหน้าแรก · ตัวเลข 3 ช่อง · ดาว · ปุ่มเพื่อนมุมขวาบน — หน้าแรกบอก "ทำอะไร" แท็บนี้บอก "มีอะไรบ้าง"

- งานเสร็จ = วงกลมทอง + เส้นขีดฆ่าสีทอง · แตะวงกลมซ้ำ = ยกเลิกติ๊ก
- พิมพ์ค้นหาแล้ววาดใหม่แค่รายการ คีย์บอร์ดไม่หุบ · ไม่เจอ = บอกตรง ๆ
- ท้ายรายการ: งานที่เสร็จแล้วทั้งหมด · ถังขยะ (มุมมองเดิม) · แตะแท็บงานอีกครั้ง = กลับรายการหลัก
- ทดสอบ (สว่าง+มืด · งาน 8 ชิ้นครบทุกกลุ่ม): กลุ่มถูกทุกกลุ่ม · ค้นหาเจอ/ไม่เจอ · ติ๊ก/ยกเลิกติ๊ก · ถังขยะแล้วกลับ · หน้าแรก/การ์ด/ผู้ใช้ใหม่ยังผ่าน · ไม่มี JS error

## 17 พฤศจิกายน 2569 · รีดีไซน์ R1 + R2: คริสตัลใส · การ์ด "ทำอันนี้ก่อน" ใหม่ (คง 0A0)

- **พื้นหลังลายคริสตัล** (เหลี่ยมคริสตัลนิ่ง สว่าง/มืด · `crystal-light.svg` / `crystal-dark.svg` สร้างด้วย `devtools/crystal-bg.py`) แทนวงแสงไล่สี · การ์ดและช่องเป็นชั้นขาวโปร่ง + ขอบรับแสงบาง ๆ เห็นลายลอดผ่าน
- **ไม่ใช้กระจกเบลอ** — แถบล่างเดิมเบลอ 30px (กินเครื่อง) → ทึบเกือบเต็ม · แท็บที่เลือกบอกด้วยสีอย่างเดียว ไม่เป็นก้อนสีวาว · สีเน้นสีเดียว (น้ำเงินใส) · หัวข้อไม่หนาเกิน
- **การ์ด "ทำอันนี้ก่อน" เป็นแผ่นคริสตัล** — สิ่งเดียวบนจอที่มีแสงเงาเต็ม · เส้นปริซึมบนขอบ (มีที่นี่ที่เดียว) · ปุ่มหลักปุ่มเดียว "เริ่มทำ" · **"เสร็จแล้ว" / "เลื่อนไปทีหลัง" เป็นปุ่มมีชื่อ** (เดิมไอคอน ✓ กับนาฬิกาให้เดา) · บรรทัดเหตุผลแตะได้ = กาง "ทำไมอันนี้ก่อน"
- **ความด่วนเป็นคำ + จุดสี** แทนดาว ★★★★★: เลยกำหนด/วันนี้ (แดง) · พรุ่งนี้ (ส้ม) · วันอื่น (เทา) — ทั้งการ์ดและรายการบนหน้าแรก
- ข้อมูลและลำดับงานยังมาจาก `focusPlan()` ก้อนเดิม · ปุ่มเรียกฟังก์ชันเดิม (startFocus · toggleDone · notNow)
- ยังไม่แตะ: แท็บงาน (R3) · ฉัน/ตั้งค่า (R4) · ฟอร์ม/กล่องเข้า (R5)
- ทดสอบ (เบราว์เซอร์ 375×812 สว่าง+มืด): หน้าแรกไม่ล้นจอ · ปุ่มเริ่ม/เสร็จแล้ว/เลื่อน/ทำไม ทำงาน · จดงาน/พูด/รูป/ปุ่มลัด/ผู้ใช้ใหม่ ผ่าน · ไม่มี JS error · สลับแท็บเฉลี่ย ~190 ms เท่าเดิม (ไม่ช้าลง) · ยังไม่ได้ลองมือถือจริง

## 16 พฤศจิกายน 2569 · เป้า 30 วินาที รอบ 3: จดโดยไม่ต้องเปิดแอป (คง 0A0)

- **สวิตช์ "ส่งงานที่ส่งเข้ามา มาที่ Clear"** บนสุดของจอตัวเชื่อม — LINE · แตะหลังเครื่อง (iPhone) · Classroom/ปฏิทิน เข้า Clear อย่างเดียว แอปหลักไม่ได้รับ · ปิด = กลับเป็นแบบเดิม (แอปไหนเปิดก่อนได้ไป)
- ต้องรัน `supabase/migrations/20261116130000_clear_inbox_route.sql` — ตาราง `inbox_route` (ผู้ใช้เลือกเอง) · `inbox_items_clear` · trigger ย้ายแถวตอนเขียน · **ไม่ต้องแก้แอปหลักหรือ Edge Function** · ยังไม่รัน = สวิตช์บอกว่ายังเปิดไม่ได้ และ Clear ดึงจากทางเดิมเหมือนก่อน
- Clear ดึงงานจากทั้งสองตาราง และฟังงานเข้าแบบทันที (realtime) ทั้งคู่
- **แชร์ข้อความเข้าแอป (Android)**: แกะแล้วเข้าแผนได้เลย = อยู่หน้าแรก + "บันทึกแล้ว" (เดิมพาไปกล่องเข้าทุกครั้ง) · ต้องให้คนดู = กล่องเข้าตามเดิม
- ทางเข้าใหม่: แท็บฉัน › **จดงานโดยไม่ต้องเปิดแอป** (LINE · แตะหลังเครื่อง · แชร์ · Classroom อยู่ในจอเดียว)
- **แก้บั๊กเดิม**: โหลดรายการตัวเชื่อมล้มเร็ว (ออฟไลน์ · เซิร์ฟเวอร์ปฏิเสธ) แล้วจอตัวเชื่อม/กล่องเข้าวนลองใหม่ไม่หยุด → พัก 30 วิก่อนลองใหม่ (แอปหลักยังมีบั๊กนี้)
- ข้อแลกที่รู้อยู่ (บัญชีที่เปิดสวิตช์): โควตา 30 ครั้ง/ชม. ของแตะหลังเครื่องไม่นับ · แจ้งเตือนรอบเช้าของงาน Classroom ที่พักไว้ช่วงกลางคืนไม่ส่ง — แก้ได้ภายหลังที่ Edge Function
- ทดสอบ: SQL บน Postgres จำลอง 13/13 (ยังไม่เลือก = เหมือนเดิม · เลือกแล้วย้ายครบทุกช่อง · บัญชีอื่นไม่โดน · ผู้ใช้เขียนเองก็ย้าย · อ่าน/เปลี่ยนของคนอื่นไม่ได้ · ลบบัญชีหายตาม) · ในเบราว์เซอร์ (Supabase จำลอง): สวิตช์ทั้งสามสถานะ · เปิดแล้วบันทึกลงฐาน · ดึงงานจากทั้งสองตารางแล้วมาร์คใช้แล้ว · แชร์ → หน้าแรก + บันทึก · ทางเข้าในแท็บฉัน · รอบ 1–2 และหน้าแรกยังผ่าน · ยังไม่ได้ลองกับ Supabase จริง/LINE จริง/มือถือจริง

## 16 พฤศจิกายน 2569 · เป้า 30 วินาที รอบ 2: พูดในช่องเดิม · ถ่ายรูปไม่ต้องครอบ (คง 0A0)

- **แตะไมค์ → พูด → หยุดพูด = บันทึกเอง** ในช่องจดงานบนหน้าแรก (เดิมพาไปจอสแกน → จอแกะ → ฟอร์มยืนยัน) · คำขึ้นในช่องระหว่างพูดพร้อมชิปผลแกะ · เว้น 0.7 วิให้เห็นก่อนบันทึก แตะช่องเพื่อแก้ = ไม่บันทึกเอง · มี "เลิกทำ" · แตะไมค์ซ้ำ = หยุดฟัง · ได้ยินไม่ชัด/ไม่อนุญาตไมค์/ไม่มีเน็ต = บอกเหตุผล · เบราว์เซอร์ที่แปลงเสียงไม่ได้ = ทางเดิม
- **แตะกล้อง → ถ่าย → AI อ่านทั้งรูปเลย** ไม่ผ่านจอครอบ · AI อ่านได้ครบ (วิชา + กำหนดส่ง + ชื่องาน) และไม่ซ้ำกับงานที่มี = บันทึกเลยพร้อม "เลิกทำ" กลับหน้าแรก · ไม่ครบ/คล้ายงานเดิม = ฟอร์มยืนยันตามเดิม
- การขอยินยอมครั้งแรก · ออฟไลน์/ไม่ยินยอม/AI ล้ม = อ่านในเครื่อง → ฟอร์ม ยังเป็นทางเดิมทุกอย่าง (ทางสำรองห้ามถอด) · สแกนจากทางอื่นยังผ่านจอครอบ
- **ยังไม่ได้ทำ "เก็บรูปไว้ก่อน แกะทีหลัง"** — ต้องมีคิวรูปในเครื่องกับการอ่านเบื้องหลังที่รอดตอนปิดแอป รอบนี้เลือกตัดจอครอบ + ฟอร์มแทน
- ทดสอบ (เสียงและผล AI จำลอง · ไม่ใช่มือถือจริง): พูด "ฟิสิกส์ การบ้านบทที่ สาม ส่ง พรุ่งนี้" → ฟิสิกส์ · การบ้านบทที่ 3 · มีกำหนดส่ง · บันทึกเอง · เสียงสั้น = ไม่บันทึก + บอก · รูปที่อ่านครบ = บันทึกเลย · ไม่มีกำหนดส่ง = ไม่บันทึกเอง · ไม่ได้มาจากปุ่มกล้อง Clear = ไม่บันทึกเอง · ปุ่มกล้อง Clear ข้ามจอครอบ ทางอื่นยังเข้าจอครอบ · หน้าแรกเดิมผ่านครบ · ไม่มี JS error
