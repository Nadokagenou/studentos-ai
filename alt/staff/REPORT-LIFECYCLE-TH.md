# หมวดรายงานและการลบจาก Control Room — 16 ตุลาคม 2569

ติดตั้ง migration studentos_report_lifecycle แล้ว และ staff-console รุ่น 4 ACTIVE; staff-notify คงรุ่น 4 เดิม ผลตรวจสิทธิ์จริง: anon/user เรียก RPC ทีมไม่ได้ และอ่าน archive table ไม่ได้ เปิด RLS แล้ว ไม่มี security advisory ของส่วนใหม่

ก่อนเผยแพร่ ตรวจรายงานจริงยังมี 2 รายงานเนื้อหาและ 1 บั๊ก ถังขยะยังว่าง ไม่มีการย้ายหรือลบข้อมูลจริงในการทดสอบ

## พฤติกรรม

- รอดำเนินการ: รายงานที่เปิดอยู่ กำลังตรวจ หรือขอข้อมูลเพิ่มเติม
- แก้เสร็จแล้ว: บั๊กสถานะ resolved และรายงานเนื้อหาสถานะ closed แยกจากงานที่ค้าง ไม่ต้องไล่ดูในลิสต์รวม
- ถังขยะ: กด “ลบจากรายการ” ได้เฉพาะเรื่องที่จบแล้ว มีข้อความยืนยันและปุ่มกู้คืนไปหมวดแก้เสร็จแล้ว
- เรื่องที่จบแล้วเปิดตรวจใหม่ได้ จะกลับไปหมวดรอดำเนินการ
- ดูรายละเอียดและประวัติของแต่ละเรื่องได้ รายงานเนื้อหาใช้ประวัติ staff_audit เดิม จึงไม่เริ่มประวัติใหม่หลังอัปเดต
- ประวัติการจัดการส่วนกลางยังเป็นบันทึกที่แก้ทับ/ลบจากหน้านี้ไม่ได้ การย้ายรายงานเข้าถังขยะและกู้คืนถูกบันทึกด้วย

รายงานเนื้อหา/บัญชีรับจากปุ่มรายงานโพสต์ คำตอบ โปรไฟล์ หรือหัวข้อในแอป เช่น สแปม/กลั่นแกล้ง ไม่ใช่บั๊กแอป และไม่ใช่ข้อมูลจำลองของ production หน้า preview.html เท่านั้นที่มีข้อมูลตัวอย่าง

## ขอบเขตข้อมูลและสิทธิ์

- เพิ่ม staff_report_archive เพื่อจัดรายการในหลังบ้าน ไม่ DELETE รายงานต้นฉบับ/เนื้อหา/บัญชี ไม่เปลี่ยนการซ่อนเนื้อหาตามเกณฑ์รายงานเดิม และไม่ลบประวัติที่ผู้รายงานบั๊กเห็น
- RPC staff_report_command รับเฉพาะ service_role หลัง staff-console ตรวจ Supabase JWT/GitHub identity/สิทธิ์เขียน repo ตามเดิม
- ตรวจชนิดและรหัสรายงาน หมวด สถานะ และ request_id ทั้ง Edge และฐานข้อมูล; retry ไม่เพิ่มรายการประวัติหรือสลับสถานะซ้ำ
- เซิร์ฟเวอร์ไม่ให้ย้ายเรื่องค้างเข้าถังขยะ และไม่ให้แก้สถานะเรื่องที่อยู่ในถังขยะจนกว่าจะกู้คืน
- อ่านแต่ละหมวดครั้งละ 20 รายการ ประวัติแสดง 100 เหตุการณ์ล่าสุด ไม่เผย reporter/target identifier ให้หน้ารายการเกินกว่ารหัสเรื่องเดิม
- ไม่เพิ่มเส้นทางประกาศ โทเคน หรือการส่ง Push
