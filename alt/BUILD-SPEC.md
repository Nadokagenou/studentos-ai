## 0. อ่านก่อนเริ่ม

เอกสารนี้มี 3 ส่วนที่ห้ามสลับลำดับกัน:

1. **§1–§3 คือกติกา** — เป้าหมาย ข้อห้าม และสิ่งที่มีอยู่แล้ว อ่านให้จบก่อนแตะโค้ด

## 2. สถานะปัจจุบัน

### สถาปัตยกรรม

Vanilla JS ล้วน · **ไม่มี build step ไม่มี npm ไม่มี framework** · เปิดไฟล์ผ่าน http แล้วทำงานได้เลย
ทุกจอเป็น `<div class="screen">` อยู่ใน `index.html` ไฟล์เดียว สลับด้วย `go(id)` ซึ่งเรียก `renderAll()` ทุกครั้ง

| ไฟล์ | ขนาด | หน้าที่ |
|---|---|---|

| `app.js` | 380 KB | UI ทั้งหมด · state · localStorage · OCR · เกม · cloud sync |
| `engine.js` | 64 KB | parser ไทย · `priorityInfo` · `buildDayPlan` — **หัวใจของโปรดักต์** |
| `context.js` | 23 KB | ตารางเรียน/กิจวัตร → คำนวณช่องว่างจริง |
| `inbox.js` | 25 KB | กล่องเข้า · `AUTO_ACCEPT = 0.8` |
| `linelink.js` | 11 KB | ผูกบัญชีกับกลุ่ม LINE |
| `brain.js` | 11 KB | เรียนรู้พฤติกรรมผู้ใช้ (ยังใช้งานน้อย) |

### Data model

**`localStorage['studentos.alt.v1']`**
```js
{
  tasks: [Task],
  settings: { name: string, freeHours: number, friends: [], brain: {...} },
  sessions: [{ id, taskId, start: ISO, end: ISO, min: number }],
  running: { taskId, start: ISO } | null
}
```

**Task**
```js
{
  id: string,            // uid()
  type: 'homework' | 'exam' | 'activity' | 'reminder',
  isExam: boolean,       // ฟิลด์เก่า — taskType() ยัง fallback มาอ่านตัวนี้
  subject: string,       // จาก SUBJECTS · 'อื่น ๆ' ถ้าไม่รู้
  detail: string,
  teacher: string,
  scorePct: number|null, // null = ไม่รู้ (ห้ามตีความว่า 0 — ดู §4)
  estMin: number,        // นาทีที่ประเมินว่าต้องใช้
  due: ISO|null,
  done: boolean,
  doneAt: ISO|null,
  progress: 0..100,      // มีฟิลด์แต่ยังไม่มีใครเขียนนอกจากฟอร์ม — ดูบั๊ก M3
  userStars: 1..5|null,  // ผู้ใช้กำหนดเอง override AI
  createdAt: ISO,
  fromScan: boolean,     // ดูบั๊ก m1
  snoozedAt: ISO|null,
  snoozeCount: number,
  remindedAt / remindedStage,
  deleted: boolean, deletedAt: ISO   // soft delete
}
```

**`localStorage['studentos.alt.ctx']`** — แยกก้อนจากงานโดยตั้งใจ (ลบได้โดยงานไม่หาย)
```js
{
  prefs: { wake:'06:00', sleep:'22:30', noWorkAfter:'21:30',
           breakMin:10, maxRunMin:50, minBlockMin:20 },
  classes:  [{ id, subject, start:'08:00', end:'16:00', weekday:[1,2,3,4,5] }],
  routines: [{ id, title, kind, start, end, weekday:[...] }]
}
```
`weekday` ใช้เลขเดียวกับ `Date.getDay()` (0 = อาทิตย์) · `weekday: null` = ทุกวัน

**คีย์อื่น** `studentos.alt.theme` · `studentos.alt.lastScreen` · `studentos.alt.skipLogin` · `studentos.alt.widget` · `studentos.legacyMigrated`

## 3. ข้อห้ามเด็ดขาด

> ผิดข้อไหนข้อหนึ่ง = ข้อมูลของคนที่ใช้อยู่หายถาวร หรือแอปเปิดไม่ขึ้น

| # | ห้าม | เพราะ |
|---|---|---|
| 1 | **เปลี่ยนชื่อคีย์ `studentos.alt.*`** | คีย์คือที่อยู่ของข้อมูลผู้ใช้ เปลี่ยนเมื่อไหร่ทุกเครื่องกลายเป็นแอปเปล่าทันที กู้ไม่ได้ ชื่อ "alt" เป็นเรื่องภายใน ผู้ใช้ไม่มีทางเห็น |
| 2 | **ใส่ build step / npm / framework** | เครื่องที่ dev อยู่ไม่มี node · deploy คือ push ขึ้น GitHub Pages ตรง ๆ |
| 3 | **ลบฟิลด์เก่าออกจาก Task** | `isExam` ยังถูกอ่านโดย `taskType()` เพื่อรองรับข้อมูลเก่า |
| 4 | **ให้ `snooze` เขียนทับ `due`** | `due` คือเส้นตายที่ครูตั้ง ไม่ใช่ของผู้ใช้ (ดูบั๊ก M4) |
| 5 | **ลดค่า `AUTO_ACCEPT` ต่ำกว่า 0.8** | เกณฑ์ auto-file ต่ำกว่านี้ = งานผิดไหลเข้าแผนเงียบ ๆ |
| 6 | **ใส่ API key ลงฝั่ง browser** | ทุก secret อยู่ใน Supabase Edge Function เท่านั้น |
| 7 | **ลืมขึ้นเลข `CACHE` ใน `sw.js` ตอนปล่อย** | service worker จะเสิร์ฟไฟล์เก่า แก้ไปก็เหมือนไม่ได้แก้ |
| 8 | **เอาหน้ายืนยัน (`scr-form`) ออก** | ทุกงานที่ AI อ่านต้องผ่านตาคนก่อนเสมอ เป็นจุดที่พิตช์ใช้ตอบเรื่อง AI อ่านผิด |
| 9 | **ทำให้ต้องต่อเน็ตถึงจะใช้ได้** | เป็น PWA ใช้ offline ได้ (ยกเว้น OCR) |
| 10 | **เก็บ availability เป็นข้อมูล** | ต้องคำนวณสดจาก `freeSlots()` เสมอ ไม่งั้นมีความจริงสองชุดที่ขัดกัน |

**เรื่อง deploy** — push ขึ้น `main` = ขึ้นเว็บจริงทันที ไม่มีอะไรกั้น ทำงานบน branch เสมอ

## 4. Priority Engine (หัวใจ — สเปกเต็ม)

### หลักคิด: สองชั้น ห้ามยุบเป็นชั้นเดียว

```
ชั้น 1  ความสำคัญ     "งานไหนใหญ่กว่า"      → คะแนน
ชั้น 2  ความเป็นไปได้  "งานไหนหมดโอกาสก่อน"  → ตัวกรอง
```

สอบกลางภาค 30% สองชั่วโมง **สำคัญกว่า** ใบงาน 10% หนึ่งชั่วโมงจริง
แต่สอบยังมีวันพรุ่งนี้ ส่วนใบงานที่ส่งพรุ่งนี้เช้าไม่มีแล้ว — **งานที่หมดโอกาสก่อนต้องได้ทำก่อน**

### สูตรชั้น 1 (ทำแล้ว อยู่ใน `priorityInfo`)

```js
// ความด่วน — เส้นโค้งต่อเนื่อง ห้ามกลับไปเป็นบันได
effHours = hoursLeft / (1 + prepHours/24)     // exam prepHours=48 → หารสาม
urgency  = max(2, round(60 - 7 * log2(1 + max(0, effHours))))
// เลยกำหนดแล้ว → 65 คงที่ (ต้องสูงกว่าเพดานเส้นโค้ง)

// คะแนนเก็บ — เบากว่าความด่วนเสมอ
scoreTerm = scorePct != null ? min(15, round(scorePct/2)) : 6   // null = ค่ากลาง ไม่ใช่ 0

// ขนาดงาน (เฉพาะ type ที่ schedulable)
need = remainingMin(task)
sizeTerm = need >= 90 ? 15 : need >= 45 ? 9 : 4

// ชั้น 2 ป้อนกลับเข้าคะแนน
lastChanceBonus = isLastChanceToday(task, now) ? 18 : 0

score = urgency + scoreTerm + sizeTerm + lastChanceBonus
stars = score>=52 ? 5 : score>=44 ? 4 : score>=32 ? 3 : score>=22 ? 2 : 1
```

**userStars override** — ผู้ใช้ตั้งเองแล้วต้องชนะ AI: `score = userStars*20 + max(0, 15 - hoursLeft/12)`

**กิจกรรม/เตือนความจำ** (`activity`, `reminder`) ใช้บันไดแยกต่างหาก เพราะเป็นเหตุการณ์ตามเวลา ไม่ใช่งานที่ต้องเจียดเวลา — อย่าเอาไปรวมกับเส้นโค้ง

**เหตุผล (`reasons[]`)** — คำนวณอยู่แล้วทุกใบ `reasons[0]` คือเหตุผลหลัก ต้องเอาไปแสดงบน UI (ดู §6)

### สูตรชั้น 2 (ทำแล้ว)

```js
isLastChanceToday(task, now):
  ถ้าไม่มี due หรือเลยกำหนดแล้ว → false
  need = remainingMin(task)
  return freeMinutesBefore(due, now, {skipToday:true, stopAt:need}) < need
```

แล้ว `buildDayPlan` ล็อกงานพวกนี้เข้าแผนวันนี้ก่อนทุกอย่าง (`mustToday`) เรียงตามเส้นตาย

**overflow ต้องแยกสองแบบ**
- `missed: true` → ไม่มีช่องว่างวันไหนเหลือก่อนเส้นตายแล้ว = **พลาดส่ง** ต้องขึ้นสีแดง
- `missed: false` → ย้ายไปวันหลังได้จริง สีเหลืองพอ

## 5. Information Architecture เป้าหมาย

### ปัญหาของโครงปัจจุบัน

| ปัญหา | รายละเอียด |
|---|---|
| **หน้าแรกมีสองหน้า** | `scr-menu` (การ์ด "ควรทำก่อน" + ทางลัด 5 ใบ) กับ `scr-home` (ประโยค AI + Top 3) ตอบคำถามเดียวกันคนละแบบ อยู่ติดกันบนแถบล่าง |
| **จอที่ตอบคำถามได้ตรงสุด ซ่อนลึกสุด** | `scr-plan` เป็นจอเดียวที่บอก "20:40–21:00 · งานนี้ · 20 นาที · [เริ่มจับเวลา]" มีทางเข้าเดียวคือปุ่มในกล่อง AI ของ `scr-home` |
| **รายการงานถูกวาดสามรอบ** | `scr-home` (Top 3) · `scr-tasks` (ทั้งหมด) · `scr-timeline` (ตามวันส่ง) |

### โครงเป้าหมาย: 5 แท็บ → 4

```
┌──────────┬──────────┬──────────┬──────────┐
│  วันนี้   │   งาน    │  + เพิ่ม  │   ฉัน    │
└──────────┴──────────┴──────────┴──────────┘
```

| แท็บ | จอเดิมที่ยุบเข้ามา | ตอบคำถาม |
|---|---|---|
| **วันนี้** | `scr-menu` + `scr-home` + `scr-plan` | "ตอนนี้ควรทำอะไร" |
| **งาน** | `scr-tasks` + `scr-timeline` (2 มุมมอง) | "มีอะไรค้าง / อาทิตย์นี้วันไหนหนัก" |
| **เพิ่ม** | `scr-scan` + กล่องเข้าขึ้นมาบนสุด | "เอางานเข้าระบบให้ไว" |
| **ฉัน** | `scr-profile` (บริบทขึ้นบนสุด · เกมลงล่าง) | "ปรับให้ตรงชีวิตฉัน" |

**ห้ามลบ screen id ทิ้งเฉย ๆ** — `go('scr-tasks')` ยังถูกเรียกจากหลายที่ รวมถึง `lastScreen` ที่จำไว้ตอนสลับแอป

```js
  'scr-tasks':    ['scr-home', 'list'],
  'scr-timeline': ['scr-home', 'days'],
  'scr-plan':     ['scr-menu', null],
```

```
│ แผนวันนี้         จัดให้แล้ว 50 จาก 50 นาที│  ← buildDayPlan (ยก scr-plan มา)
│ 21:10  ฟิสิกส์ 40 นาที      [เริ่มจับเวลา] │

│ ⚠ ทำไม่ทันถ้าไม่ทำวันนี้ (กล่องแดง)         │
│ เวลาวันนี้ไม่พอ — ย้ายไปวันหลังได้ (เหลือง) │
├─────────────────────────────────────────┤
│ ▸ 3  งานที่เหลือ — ยังไม่ต้องคิดตอนนี้     │  ← พับไว้เสมอ

```

**กฎที่ทำให้มันลดภาระจริง**

1. **หนึ่งงาน หนึ่ง CTA** — ห้ามมีสองการ์ดที่ป้ายเท่ากัน สามตัวเลือกที่ดูเท่ากัน = ยังต้องตัดสินใจอยู่ดี
2. **"ทำไมตอนนี้" ต้องมาจาก `reasons`** ที่เอนจินคำนวณไว้แล้ว ห้ามเป็นข้อความกำลังใจ
3. **"ยังไม่ไหวตอนนี้" ห้ามแตะ `due`** — ใช้ฟิลด์ใหม่ `notNowAt` (หรือ `plannedFor`) แล้วให้การ์ด NOW ข้ามงานนั้นไป 3 ชม. พร้อมปุ่มเลิกทำใน toast
4. **ติ๊กเสร็จ → การ์ดถัดไปเลื่อนขึ้นมาแทนทันที** พร้อมชื่องาน (ตอนนี้ `celebrateCopy()` พูดว่า "ไปต่องานถัดไปกันเลย!" โดยไม่บอกว่างานไหน — ต้องแก้)
5. **ถอดตารางทางลัด 5 ใบออก** — การถามว่า "จะไปหน้าไหน" คือการตัดสินใจที่แถบล่างตอบอยู่แล้ว
6. **หยุดเด้ง modal เช็คอินตอนเปิดแอป** — ให้เป็นจุดแดงบนแท็บ "ฉัน" แทน
7. **ทำเกินเวลา → แถบเดียว** `⚠ ใช้เวลาเกินแผน 35 นาที · [จัดเวลาที่เหลือใหม่]`
   (`buildDayPlan(now)` คิดใหม่ทุกครั้งที่วาดอยู่แล้ว — ที่ขาดคือการบอกผู้ใช้ว่ามันคิดใหม่แล้ว)

### 6.2 แท็บ "งาน"

```
┌─────────────────────────────────────────┐
│ งาน                                      │
│ ค้างอยู่ 4 · เสร็จแล้ว 1                   │
│ ┌───────────┬───────────┐                │
│ │ ✓ รายการ  │  📅 7 วัน │                │  ← segmented
│ └───────────┴───────────┘                │
└─────────────────────────────────────────┘
```

**มุมมอง "รายการ"**
- ตัวกรอง 3 อัน: ค้างอยู่ / เสร็จแล้ว / ทั้งหมด + ปุ่มถังขยะท้ายหน้า
- งานค้าง = การ์ดเต็มใบพร้อมเลขลำดับ **ทั้งรายการ** ไม่ใช่แค่ 3 ใบแรก (เดิมงานอันดับ 4 ถูกลดชั้นเป็นแถวเปล่า ทั้งที่ก็คืองานที่ต้องทำเหมือนกัน)
- ปัดขวา = เสร็จ · ปัดซ้าย = เลื่อน (ต้องผูก listener ที่ `#scr-home` ไม่ใช่กล่องข้างในที่ถูกเขียนทับทุก render)
- งานที่เสร็จแล้ว = แถวเตี้ย (เป็นบันทึก ไม่ใช่สิ่งที่ต้องตัดสินใจ)

**มุมมอง "7 วัน" — จุดอ่อนที่สุดของแอปตอนนี้**

ปัญหา: แต่ละวันบอกแค่ "ว่าง 4.5 ชม." ซึ่งเป็น**ครึ่งเดียวของคำถาม**
เวลาว่างสี่ชั่วโมงครึ่งเป็นข่าวดีหรือร้าย ขึ้นอยู่กับว่ามีงานรออยู่กี่ชั่วโมง

ต้องเป็น **load vs capacity** ต่อวัน:
```
วันจันทร์  17 ส.ค.              นั่งไหว 3 ชม.
[▓▓▓▓▓▓░░░░░░░░░░░░]              ← needMin / budget
ต้องทำ 1 ชม. 30 นาที · ว่างจริง 4 ชม. 30 นาที
  03:22  ภาษาอังกฤษ Essay   สำคัญ · ~90 นาที
```
- แถบเต็ม/ล้น → วันนั้นเป็นสีเตือน
- `tlBuildDays()` คำนวณ `capAcc` / `needAcc` / `tight` / `shortMin` ไว้ให้แล้ว — แค่ยังไม่ได้เอามาแสดงให้เห็น
- คำเตือนต้องบอกชื่องานที่ควรเริ่มก่อน (ใบใหญ่สุดของวันนั้น) ไม่ใช่ข้อความกลาง ๆ
- **หน่วยเวลาต้องเป็นนาทีเมื่อต่ำกว่า 1 ชม.** — "0.3 ชม." ไม่มีใครแปลงในหัวทัน

## 8. Design System

### Tokens (อย่าใส่สี hex ตรง ๆ ในคอมโพเนนต์)

| token | ใช้กับ |
|---|---|
| `--scr` `--card` `--card2` `--surface` | พื้น 3 ชั้น |
| `--ink` `--muted` `--faint` | ตัวอักษร 3 ระดับ |
| `--fill` / `--on-fill` | **พื้นทึบสีเน้น + สิ่งที่วางทับ** (ปุ่ม แท็บที่เลือก ชิปไอคอน) |
| `--blue` / `--blue-soft` | สีตัวอักษรบนพื้นเข้ม / พื้นจาง |
| `--alert` `--warn` `--good` + `-soft` | แดง เหลือง เขียว |
| `--pri-red` `--pri-yellow` `--pri-green` | ระดับความสำคัญ — **คงที่ทุกธีม** เพื่อให้ความหมายไม่เปลี่ยนตามธีม |
| `--tile-plan/tasks/route/me` + `--tile-on` | สีเฉพาะของไทล์แต่ละใบบนหน้าแรก |

มี 12 ธีม · ธีมที่ไม่ได้ประกาศ token ทับ จะตกกลับมาที่ค่าตั้งต้นเอง — **อย่าใส่สี hex ที่ `:root`** ไม่งั้นธีมเขียว/ม่วงจะได้ชิปสีน้ำเงินติดมาด้วย

### กฎ 60/30/10
พื้น 60% · ชั้นรอง 30% · สีเน้น 10% เฉพาะของที่ "กดแล้วเกิดอะไรขึ้น"
ข้อยกเว้นที่ตกลงกันแล้ว: ไทล์หน้าแรกแยกสีได้ 4 เฉด แต่ต้องอยู่ในตระกูลน้ำเงิน

### ภาษา
- ภาษาไทยทั้งหมด · ไม่เว้นวรรคระหว่างคำ ใช้ ` · ` คั่นข้อมูล
- ชื่องานยาวใส่อัญประกาศคั่น: `เริ่มที่"ทำโจทย์บทที่ 4"ก่อน` ไม่ใช่เว้นวรรค
- ตัวเลขเวลาต่ำกว่า 1 ชม. ใช้ "นาที"
- **ห้ามข้อความกำลังใจแทนข้อมูล** — "บริหารเวลาให้ดี" ไม่มีค่า · "เหลือ 3 ชม. ยังไม่ได้เริ่ม" มีค่า

### คอมเมนต์ในโค้ด
โปรเจกต์นี้เขียนคอมเมนต์เป็นภาษาไทยอธิบาย **"ทำไม"** ไม่ใช่ "ทำอะไร" และมักเล่าว่าของเดิมพังยังไง
ทำต่อให้เหมือนกัน — คอมเมนต์ที่บอกแค่ว่าโค้ดทำอะไรคือคอมเมนต์ที่ไม่ต้องมี
