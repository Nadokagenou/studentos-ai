## 5. กฎเหล็กที่ต้องรู้ก่อนแก้

1. **ห้ามแก้ `style.css`** — ทุกอย่างของ ALT ไปอยู่ใน `alt.css` เท่านั้น (โหลดทีหลังจึงทับได้)
2. **เพิ่มธีมใหม่ต้องแก้ 3 ที่ให้ตรงกัน** ไม่งั้นจอแรกกะพริบ/ธีมไม่ถูกจำ:
   - `THEME_BAR` + `THEME_NAME` ใน `app.js`
   - ตาราง `BAR` ในสคริปต์ `<head>` ของ `index.html`
   - บล็อกโทเคนใน `alt.css`
3. **ขึ้นเวอร์ชัน** = แก้ `APP_VERSION` (app.js) + `CACHE` (sw.js) + title/meta/manifest/README/PATCHNOTES
   ป้ายเลขรุ่นกลางบนจอดึงจาก `APP_VERSION` อัตโนมัติ
4. **ดีไซน์เป็น px ล้วน** — ปรับขนาดตัวอักษรจึงใช้ `zoom: var(--fs)` กับกล่องเนื้อหา ไม่ใช่ `font-size` ที่ราก
5. **การ์ด `.brief` ห้ามใส่ในกฎ "การ์ดกึ่งโปร่ง"** — มันใช้พื้นไล่สีเข้ม + ตัวอักษรขาว
   เอาสีการ์ด (ขาว) ไปทับเมื่อไหร่ ตัวหนังสือหายทั้งใบ (เคยพลาดมาแล้ว 2 ครั้ง)
6. **หน้าแรก (`scr-menu`) ต้องไม่ต้องเลื่อน** — ทุกครั้งที่เพิ่มของต้องวัด `scrollHeight - clientHeight`
   ต้องเป็น 0 ทั้ง 4 แบบวิดเจ็ต ที่ 375×812
7. **แจ้งเตือนต้องยิงผ่าน service worker** (`registration.showNotification`) — `new Notification()` ใช้ไม่ได้บน Chrome มือถือ

## 10. วิธีทดสอบ (ไม่มีภาพหน้าจอ)

แพเนล Browser มักถูกซ่อน → `computer{action:"screenshot"}` ใช้ไม่ได้ และ `requestAnimationFrame` ไม่เดิน
**ให้ทดสอบด้วย `javascript_tool` แทน** เรียกฟังก์ชันของแอปตรง ๆ แล้ววัดผลจาก DOM:

```js
go('scr-menu');                      // เปลี่ยนจอ
setTheme('ocean'); setWidget('note'); setFontScale('l');
loadSample();                        // ข้อมูลตัวอย่าง 4 งาน
document.getElementById('scr-menu').scrollHeight - clientHeight   // วัดว่าต้องเลื่อนไหม
getComputedStyle(el).animationName                                 // เช็คอนิเมชัน
```

**กับดักที่เคยเจอ:**
- CSS transition ไม่เดินตอนแพเนลถูกซ่อน → วัด opacity แล้วได้ค่าเริ่มต้น ให้ปิด transition ชั่วคราวก่อนวัด
- `read_console_messages` เก็บ log ข้ามการรีโหลด — error เก่าอาจหลอกได้ ให้ดูเวลา/เนื้อหาประกอบ
- ระยะเวลาระหว่าง `navigate` กับ `javascript_exec` ประมาณ 4 วินาที — splash หายไปแล้วเมื่อสคริปต์เริ่มรัน

## 11. สิ่งที่ผู้ใช้ชอบ / ไม่ชอบ

- **ตอบเป็นภาษาไทย** และ **ใส่คำลงท้ายสุภาพ (ครับ) ให้บ่อยขึ้น แต่ไม่ต้องทุกประโยค**
  (ใส่ตรงประโยคสรุป/ถาม/เสนอทางเลือก ไม่ต้องใส่ในตาราง หัวข้อ หรือรายการผลทดสอบ)
- ชอบให้ **บอกตรง ๆ ว่าอะไรทำได้จริง อะไรยังไม่ได้** — ห้ามแต่งตัวเลขหรืออ้างว่าเทสต์แล้วทั้งที่ไม่ได้เทสต์

- คอมมิตเมสเสจเป็น **ภาษาอังกฤษ** เล่าเป็นย่อหน้า อธิบายเหตุผลไม่ใช่แค่รายการสิ่งที่ทำ
- ชื่อเวอร์ชันเขาเป็นคนตั้งเอง (`1A5` → `1A6` → `1A6M` → `1A6M2` → `1A6M3`) **อย่าตั้งเอง**
- ส่งภาพหน้าจอที่วงด้วยปากกามาบ่อย — เส้นที่วง = "ตรงนี้" ไม่ใช่สีที่ต้องการ

**กฎที่ผู้ใช้สั่งไว้:**
- แอป**ห้ามบอกว่ามีโค้ดอะไรบ้าง หรือโค้ดไหนทำอะไร** — ทั้งใน UI, placeholder, ข้อความตอนพิมพ์ผิด
  และในแพตช์โน้ต · ตอนผิดบอกได้แค่ "ใช้ไม่ได้" ห้ามใบ้ว่าใกล้เคียงแค่ไหน
- **โค้ดมีเฉพาะรุ่น 1A6M3** — บังคับด้วย `CODE_VERSION` ที่เทียบกับ `APP_VERSION`
  ขึ้นรุ่นใหม่ = ช่องหายเองและโค้ดหมดอายุเอง **ถ้าจะให้รุ่นถัดไปใช้ได้ต้องตั้งใจแก้บรรทัดนั้น**

**สิ่งที่ต้องไม่ทำพัง:**
- โค้ดที่ปลดล็อกของ ใช้ธง `ALLBADGE_KEY` แยกต่างหาก **ห้ามไปปลอม `doneCount()`** เลขในจอผลของฉันต้องจริงเสมอ
- โค้ดที่ล้างแอป ลบเฉพาะคีย์ prefix `studentos.alt.` **ห้ามแตะข้อมูลบิลด์ตัวจริง** (`studentos.v1`)
- `clearAll()` กับ `relockSecrets()` ต้องลบ `ALLBADGE_KEY` ด้วย ไม่งั้นล้างแล้วเหรียญยังครบค้างอยู่
- โค้ดที่ล้างแอป **ยังไม่มีจังหวะถามยืนยัน** — ตั้งใจให้เป็นแบบนั้น ถ้าจะเพิ่มต้องถามผู้ใช้ก่อน
