## 4.5 เอนจินตัดสินใจ (1B76–1B79) — อ่านก่อนแตะอะไรที่เกี่ยวกับ "ควรทำอะไรก่อน"

**ทำไมถึงมี:** `priorityInfo()` ใน `engine.js` คืน `score` ที่ **ไม่มีหน่วย** — ไม่ใช่คะแนนที่จะเสีย
ไม่ใช่ความน่าจะเป็น แปลว่าพิสูจน์ไม่ได้ว่าคำแนะนำเมื่อวานถูกหรือผิด และของที่ผิดไม่ได้
ก็ปรับให้ดีขึ้นอย่างเป็นระบบไม่ได้ · ห้าไฟล์นี้เปลี่ยนคำถามเป็น
`argmin E[Loss(อนาคต | ทำ a ในช่วงถัดไป)] + κ·σ` โดยตีทุกอย่างเป็นสกุลเดียว:
**เปอร์เซ็นต์ของคะแนนรวมทั้งเทอมที่คาดว่าจะเสีย**

**ลำดับการโหลดใน `index.html` ห้ามสลับ:**
`engine.js` → `context.js` → `planner.js` → `facts.js` → `profile.js` → `simulate.js`
→ `calibrate.js` → `loss.js` → `decide.js` → `app.js`

**ทางเข้าที่ควรใช้ (อย่าเรียกชั้นล่างเอง):**

| อยากรู้ | เรียก | อยู่ที่ |
|---|---|---|
| งานใบนี้ยังเริ่มทันไหม | `riskFor(task, now)` | `app.js` (แคชให้แล้ว) |

### กฎเหล็กของเอนจินนี้

1. **ห้ามใช้ `Math.random()` ในทั้งห้าไฟล์** — `renderMenu` ถูกเรียกทุกนาที ตัวเลขบนการ์ด
   จะขยับเองโดยข้อมูลไม่ได้เปลี่ยน และเบนช์จะทดสอบอะไรไม่ได้เลย · ใช้ `simRng(seed)` เท่านั้น
2. **ทุกทางเลือกต้องใช้เมล็ดสุ่มชุดเดียวกัน** (common random numbers) — เผลอสุ่มคนละชุดเมื่อไหร่
   ตัวเลขกระโดดทันที และต้องเพิ่มจำนวนเส้นอีกสิบเท่ากว่าจะนิ่ง
3. **ห้ามเรียก `riskReport`/`decide` จากการ์ดทีละใบ** — นอกจากช้า มันยังผิด เพราะการ์ดที่คิดเอง
   จะไม่เห็นว่าใบอื่นจองเวลาไปแล้ว ซึ่งเป็นทั้งจุดของฟีเจอร์นี้
4. **ห้ามให้ `decideFor()` เรียก `focusPlan()`** — ตั้งแต่ 1B79 `studyPlan()` เรียก `decideFor()`
   เรียกกลับเมื่อไหร่ได้วงกลมทันที แล้วแอปค้างตั้งแต่วาดจอแรก
5. **ห้ามนับวันที่ไม่มีรอบจับเวลาเป็น "วันที่ไม่ได้ทำงาน"** (`profile.js`) — การไม่กดปุ่ม
   ไม่ใช่หลักฐานว่าไม่ได้ทำ · เคยพลาดแล้วได้ `rate 0.16` บนเครื่องที่เพิ่งติดตั้ง
6. **ห้ามให้ไฟล์ไหนเก็บรายชื่อวิชาของตัวเองอีก** — ธรรมชาติของงานอยู่ที่ `facts.js` ที่เดียว
   (เคยมีสองที่แล้วเพี้ยนคนละทาง) · และ "ว่าง" ในฟิลด์ L0 แปลว่า "ให้เดา" ไม่ใช่ "ไม่มี"
7. **`decide()` ห้ามเสนองานที่ยังติดใบอื่นอยู่** — ตัวจำลองข้ามมันถูกแล้ว คะแนนจึงดูปกติ
   ทั้งที่เริ่มไม่ได้ · เคยเชียร์ "แบบฝึกหัดบทที่ 4" ทั้งที่ยังไม่ได้อ่านบทที่ 4
8. **ค่าคงที่ของ `loss.js` ถูกรวบไว้ที่เดียวโดยตั้งใจ** — อย่าขยับตามความรู้สึก ให้ดูที่
   `calibrate.js` ว่ามันบอกว่าแม่นขึ้นหรือแย่ลง

## 10. วิธีทดสอบ (ไม่มีภาพหน้าจอ)

go('scr-menu');                      // เปลี่ยนจอ

### 17.2 เครื่องมือวัดผล — ใช้ให้เป็นก่อนแก้อะไร

`alt/devtools/ocrbench.js` · **ไม่ถูกโหลดโดยแอป** ผู้ใช้ไม่ต้องแบกน้ำหนัก

```js
// ฉีดด้วย script tag เท่านั้น ห้ามใช้ eval — const จะไม่ขึ้น global
const s = document.createElement('script');
s.src = 'devtools/ocrbench.js?v=' + Date.now();
document.head.appendChild(s);

await benchReal()    // วัดกับรูปจริง 6 ใบ ← ใช้อันนี้เป็นหลัก
await benchSkew()    // วัดเฉพาะตัวแก้ภาพเอียง เร็ว ไม่ต้องโหลด Tesseract
await benchHard()    // วัดกับใบงานที่สร้างเอง 3 ระดับความยาก
```

**เทียบหลายสูตรพร้อมกัน:**
```js
await benchReal([
  { ชื่อ:'ปัจจุบัน', opt:{ full:true } },              // สายจริงทั้งเส้น รวมรอบเก็บตก
  { ชื่อ:'ทั้งหน้าอย่างเดียว', opt:{ adaptive:true, psm:11 } },
  { ชื่อ:'เรียงบล็อก', opt:{ blocks:'stack', psm:11, stackPsm:6 } },
]);
```
`opt` รับ: `full:true` (เรียก `ocrReadCanvas` ตัวเดียวกับแอป) · `psm` · `bin:false` (ไม่ไบนารี) ·
`adaptive:true` (ให้ `ocrIsDigital` ตัดสินเอง) · `deskew:false` · `minLong` / `maxLong`
(**ไม่ระบุ = ใช้ค่าของแอป** · ระบุ `minLong:null` เองถ้าอยากปิดการขยายภาพเล็ก) ·
`blocks:'stack'|'only'|'plus'` + `stackPsm`

**กฎที่ต้องรักษาไว้:** สูตรที่ชื่อว่า "ปัจจุบัน" ต้องเป็น `{ full:true }` เสมอ
และ **ห้ามประกอบท่อเตรียมภาพขึ้นมาเองใน bench** — ให้เรียก `ocrPrepare()` ของแอป
ความเพี้ยนระหว่าง bench กับแอปเคยทำให้ตัวเลขที่รายงานไว้ผิดมาแล้ว 4 จุดพร้อมกัน
(ดูแพตช์โน้ต 1A7V หัวข้อ 13 ส.ค.)

**ชื่อที่เปลี่ยน:** ตัวโหลดรูปในไฟล์ bench ชื่อ `benchLoadSample()` แล้ว —
ห้ามตั้งชื่อ `loadSample` เพราะจะไปทับ `loadSample()` ของแอป (โหลดงานตัวอย่าง 4 งาน)

**รูปจริงอยู่ที่ `alt/devtools/samples/`** — RP = รูปถ่ายจากมือถือ · DP = ภาพดิจิทัล
เฉลยเป็น "วลีที่ต้องอ่านเจอ" อยู่ในตัวแปร `SAMPLES` ในไฟล์ bench
(ไม่ได้วัดเป็นช่องวิชา/ครู เพราะภาพชุดนี้ไม่ใช่ใบงานทุกใบ)

**การรันใช้เวลาเกิน 30 วินาที** ซึ่งเกิน timeout ของเครื่องมือ ให้สั่งแบบไม่ await
แล้วเก็บผลไว้บน `window` จากนั้นค่อยมาอ่านทีหลัง:
```js
window.__r = { done:false };
(async () => { window.__r.out = await benchReal(); window.__r.done = true; })();
// แล้วรอบถัดไปค่อยอ่าน window.__r.out
```

**แปลว่า:** ตัวอักษรคุณภาพดีพอมาตลอด · ความละเอียดพอ · โหมดถูกแล้ว
สิ่งเดียวที่เหลือคือ **การยัดทั้งหน้าเข้าไปพร้อมกันในครั้งเดียว**

**ทำไปแล้ว (13 ส.ค.) — เรียงบล็อกแล้วอ่านเพิ่มรอบเดียว**

`ocrFindBlocks()` → `ocrStackBlocks()` → `ocrReadBlocks()` ใน `app.js`
ละเลงหมึกให้ก้อนข้อความติดกัน (RLSA) → ได้กรอบก้อน → **เอาทุกก้อนมาเรียงต่อกันเป็นภาพใหม่ภาพเดียว**
แล้วอ่านเพิ่มอีกรอบด้วย PSM 6 → ต่อข้อความ**ท้าย**ผลอ่านทั้งหน้า

- ห้ามเอาไปแทนผลอ่านทั้งหน้า ให้ต่อท้ายเท่านั้น — ลำดับที่ `parseAssignment` เห็นก่อนจะได้ไม่เปลี่ยน
  (วัดแล้ว: ช่องที่แกะได้จาก RP-1/2/3 เหมือนกันเป๊ะทั้งก่อนและหลังต่อข้อความ)
- **อย่าใช้ `skewComponents()` ตรง ๆ เพื่อหาตัวอักษร** — วัดจริงกับรูปถ่าย: ชิ้นส่วนที่ได้ไม่ใช่ตัวอักษร
  RP-2 มีก้อนเดียวกินหมึก 32% ของทั้งภาพ (กล่องหัวกระดาษเชื่อมกับตัวหนังสือข้างใน)
  ส่วนที่เหลือกว่าครึ่งสูงไม่ถึง 8px ใช้ประมาณขนาดตัวอักษรด้วย `ocrTextScale()` แทน (มัธยฐานถ่วงด้วยหมึก)
- ต้องกรองก้อนด้วย **ความทึบ** (`n ≥ w*h*0.35`) ไม่งั้นกรอบใบงานที่ลากคดไปทั่วหน้าจะให้กรอบครอบ
  ขนาด 85×98% ของหน้า ซึ่งเท่ากับอ่านทั้งหน้าเหมือนเดิม

### 17.5 ปุ่ม "อ่านให้แม่นขึ้น" — โครงพร้อม ยังไม่ได้เลือกผู้ให้บริการ (13 ส.ค.)

**เพดานของ Tesseract คือลายมือไทย** ปรับภาพเท่าไหร่ก็ไม่ผ่าน ต้องพึ่งโมเดลบนเซิร์ฟเวอร์

โครงที่วางไว้แล้ว — **เปิดใช้ = เขียนอะแดปเตอร์ตัวเดียว**:

| ชิ้น | ที่อยู่ | สถานะ |
|---|---|---|
| Edge Function | `supabase/functions/ocr-assist/index.ts` | พร้อม มี `mock` ไว้ทดสอบสายไฟ |
| ตั้งค่า verify_jwt | `supabase/config.toml` | `true` จงใจ — กันคนยิงจนโควตาฟรีหมด |
| ฝั่งแอป | `ALT 1A7V: อ่านให้แม่นขึ้น` ใน `app.js` | พร้อม |
| ปุ่มบนจอสแกน | `#cloudOcrBox` ใน `index.html` | พร้อม โผล่หลังสแกนเท่านั้น |

**วิธีเปิดใช้:**
1. เขียนฟังก์ชันหนึ่งตัวใน `ADAPTERS` ของ `ocr-assist/index.ts` (รับ `{b64, mime}` คืน `{text, conf}`)
2. `supabase secrets set OCR_API_KEY=...` แล้วตั้ง `OCR_PROVIDER` เป็นชื่ออะแดปเตอร์นั้น
3. `supabase functions deploy ocr-assist`

**กฎที่ต้องรักษาไว้:**
- **ห้ามทำให้เป็นค่าเริ่มต้น** — อ่านในเครื่องต้องมาก่อนเสมอ การทำงานแบบออฟไลน์และรูปไม่ออก
  จากเครื่องเป็นจุดขายจริงของงานนี้ (ส่ง Samsung Solve for Tomorrow)
- **ห้ามใส่ API key ลงไฟล์ไหนใน repo** — เป็นสาธารณะ คีย์อยู่ใน secret ของ Supabase เท่านั้น
- **ห้ามเปลี่ยนรูปคำตอบ** `{ ok, text, conf, provider, ms }` — ฝั่งแอปอ่านแค่นี้
  เปลี่ยนเจ้าแล้วต้องไม่ต้องแก้ `app.js` เลย นั่นคือเหตุผลที่แยกชั้นนี้ออกมา
- ข้อความเตือนเรื่องรูปออกจากเครื่องบนปุ่ม **ห้ามลบหรือทำให้จางลง**

### 17.6 ที่ยังพลาดอยู่ในการอ่านในเครื่อง

**ที่ยังพลาดอยู่:** RP-2 ยังได้ 2/4 — หัว `แบบฝึกหัดที่ 10` อยู่ในกล่องทึบที่เชื่อมกับตัวอักษร
ทำให้ทั้งกล่องกลายเป็นก้อนเดียว การละเลงจึงแยกหัวออกมาไม่ได้ · `VSync` ใน DP-3 ก็ยังไม่ได้
ถ้าจะทำต่อ ให้ดูที่ **การแยกตัวอักษรออกจากกล่อง/กรอบที่มันติดอยู่** เป็นอันดับแรก

### 17.5 ช่องทดสอบที่เปิดไว้ใน `app.js`

`window.__OCR_MIN_OVERRIDE` และ `window.__OCR_MAX_OVERRIDE` — ให้เครื่องมือวัดลองค่าความละเอียดอื่นได้
**แอปจริงไม่เคยตั้งค่าพวกนี้** ค่าปกติมาจาก `OCR_MIN_LONG` / `OCR_MAX_LONG` เหมือนเดิม
ถ้าจะลบทิ้งต้องแก้ `runVariant()` ใน bench ด้วย

### 17.6 บทเรียนที่อยากฝากไว้

**วัดปลายทางเสมอ อย่าเชื่อตัวเลขกลางทาง** — ตอนทำตัวแก้ภาพเอียงรอบแรก วัดได้ว่า
"หามุมแม่น 0.1°" ซึ่งเป็นความจริง แต่พอวัดปลายทางกลับ**ไม่ช่วยอะไรเลย**
เพราะเพดานตั้งไว้ 8° ในขณะที่ตัวอ่านทนได้ถึง 10° อยู่แล้ว — ไปแม่นในช่วงที่ไม่มีใครต้องการความแม่น
ถ้าไม่ได้วัดปลายทาง ของชิ้นนั้นจะถูกนับว่า "เสร็จแล้ว" ทั้งที่ไม่ได้ช่วยอะไร

**และเครื่องมือวัดจับบั๊กได้ตั้งแต่รอบแรกที่รัน** — ตัวหามุมคืนค่าเครื่องหมายกลับด้าน
(เอียง −7° รายงานว่า +7.1°) ขนาดถูกทุกตัว ผิดแค่ทิศ ถ้าปล่อยไปจะกลายเป็นฟีเจอร์ที่
**ทำให้ภาพเอียงเป็นสองเท่าแทนที่จะแก้**
