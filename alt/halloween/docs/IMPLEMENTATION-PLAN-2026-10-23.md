## 3. กติกาที่ยืนยันแล้วและต้องรักษา

- อีเวนต์ยาว 2 สัปดาห์ และให้ลองธีมวันที่ 31 ตุลาคม; ความสัมพันธ์กับช่วงเล่นจริง วันเวลาเริ่ม–จบ และ timezone ยังไม่ยืนยัน รางวัลที่ได้รับเก็บใช้ถาวร
- 4 ไบโอม: Dutchman's Soul → Jack's Hollow → Vampire Mansion → Eternal Graveyard; สวนฟักทองอยู่ Jack's Hollow
- ช่วงเวลาที่เสนอไว้คือ 00:01–06:00 / 06:01–12:00 / 12:01–18:00 / 18:01–00:00 ต้องกำหนดขอบเขตวินาทีและเวลาอ้างอิงก่อนเขียนตารางใช้งานจริง
- บ้าน 5 หลังต่อชุด; Treat 10 Candy; Trick 50% ได้ 20 และ 50% ได้ 0; คูลดาวน์เริ่มต้น 4 ชั่วโมง; รายได้ **จากบ้าน** ไม่เกิน 300 Candy/24 ชั่วโมง ไม่ขยายเพดานนี้ไปครอบ Candy จากแหล่งอื่นเอง
- เมื่อได้ Candy มีโอกาส 60% ได้ไอเทม; ระดับ Common/Uncommon/Rare/Epic/Legendary/Secret = 40/30/15/10/4/1%; Mystical ไม่อยู่ในตารางบ้าน
- Breakthrough 10% เลือกทั้ง 4 ไบโอมเท่ากันรวมไบโอมเดิม: อยู่ไบโอมเดิมรวม 92.5%, อีกแต่ละไบโอม 2.5%
- Spectral Lantern = Abyssal rock 1 + Dutchman's Lantern 1 + 50 Candy ผ่าน Tang Q1; ผู้เคยคราฟต์ไม่เสียของซ้ำ
- ชุด Rare ทั้งสองได้จากพิธีอัญเชิญ; ธีมหลักหายากที่สุด; ของแต่งห้องหาง่าย; เหรียญได้จากซื้อครบรายการร้านที่กำหนด
- Cruor Quill ได้ Dech Q1; Dech Q3 ต้องรอวัฏจักรไบโอมถัดไปหลังส่ง Q2; ยังไม่รู้ว่า Totem นับหรือไม่
- Jack Q3 จ่าย 200 Candy **หรือ** กลุ่มวัตถุดิบ จากนั้นส่ง His head ในเฟสถัดไปก่อนรับขวานและธีม
- Win Q1 ให้ Shovel; Pumpkin ใน Jack Q2 ต้องปลูกเอง 3 ชิ้น ไม่ใช่ Rotten Pumpkin/Pumpkin carved
- Win Q2 ใช้การเล่นขุดหลุมศพให้จบ แล้วจับผีทั้งหมดภายใน 30 วินาที; อย่าเปลี่ยนเงื่อนไขขุดเป็นต้องชนะ
- Win Q4 ให้เคียว Restricted; Q5 จ่าย 50 Candy และ **แสดง** Dutchman's Soul ไม่หักของ แล้วปลดข้อจำกัดเคียวชิ้นเดิมพร้อมธีม ไม่ให้เคียวซ้ำ

## 4. จุดที่ต้องจัดข้อมูลก่อนเชื่อมระบบจริง

1. ข้อมูลไบโอมใช้รหัสยาว เช่น `dutchmans-soul`; catalog ภาพใช้รหัสสั้น เช่น `dutchman` ต้องมีตารางเชื่อมเดียว ห้ามสร้างสกุลหรือกระเป๋าคนละชุดตามหน้า
2. วัตถุดิบ/relic ใช้ inventory ID ยาว ส่วนรางวัลภาพใช้ ID เช่น `dullahan-scythe`; JSON บางจุดมี inventoryId แล้ว ต้องใช้ ID สิ่งของหลักเดียวกับรหัสภาพที่อ้างถึง ห้ามแจกซ้ำเพราะรหัสต่างกัน
3. materials.json ยังเขียน mysticalSource แบบเหมารวมว่าเคลียร์ Main Quest และ Vampire teeth ยัง sourceBiome:null ทั้งที่บท Win ยืนยันคฤหาสน์แล้ว ต้องปรับ metadata ตามข้อยืนยันนี้โดยไม่แต่งระดับดรอป
4. README บางย่อหน้ายังระบุว่าแหล่ง Shovel ไม่กำหนด ทั้งที่ส่วนท้ายและ Win Q1 ยืนยันแล้ว ต้องปรับข้อความให้สอดคล้อง
5. `null` จำนวนของใน Dech Q2/Q3 และค่าดรอปยังต้องคงสถานะรอยืนยัน เงื่อนไขที่ข้อมูลไม่ครบต้องปิดการส่งของพร้อมอธิบาย ห้ามตีเป็น 0, 1 หรือผ่านโดยอัตโนมัติ
6. Win Q5 มี consume:false / mustPossess:true และ quantity:null ให้ประเมินเป็นการครอบครองของสำหรับแสดง ห้ามส่งเข้าตัวหักไอเทมทั่วไป
7. ตรวจเครื่องมือ sync-specs.cjs ก่อนใช้: ปัจจุบันอ่านและเขียนเอกสารนอก repo ด้วย และมีการสร้าง metadata จากหลายไฟล์ ต้องจำกัดการเขียนให้อยู่ขอบเขตที่อนุญาตและไม่ให้แหล่งเก่าเขียนทับข้อกำหนดใหม่

## 5. โครงสร้างที่จะต่อยอด

ชื่อไฟล์ใหม่เป็นข้อเสนอ ยังไม่ได้สร้าง:

| ที่อยู่ | หน้าที่ |
|---|---|
| event/config.json + event/data/ | ฤดูกาล ค่ากติกาที่ยืนยัน เควส สูตร แหล่งดรอป พร้อมสถานะรอยืนยัน |
| event/core/season.js, biome.js | สถานะก่อนเปิด/เปิด/ปิด เวลาอ้างอิง วัฏจักร และ Totem เมื่อได้กติกา |
| event/core/transactions.js, houses.js, quests.js | คำสั่งเล่น การประเมินเงื่อนไข สุ่มผลครั้งเดียว รับ/ใช้ของและเปลี่ยนสถานะ |
| event/core/garden.js, shops.js, crafting.js | แปลงปลูก ร้าน หม้อ และพิธี แยกสูตรแต่ใช้ธุรกรรมร่วมกัน |
| event/games/ | Ghost Ship Hunt, เถาวัลย์, จับผิดภาพ, ขุดหลุมศพ, จับผี |
| event/ui/ | หน้าสำรวจ บ้าน กระเป๋า NPC สวน ร้าน หม้อ และพิธี ใช้ภาพเดิมจาก rewards/ |
| rewards/ownership.js, storage.js | สิทธิ์ถาวร การอ่าน/เก็บสิทธิ์แยกบัญชี และตัวเชื่อมระบบข้อมูลเดิม; ไม่ import event/ |
| rewards/ เดิม | ภาพ ธีม ชุด ของห้อง เอฟเฟกต์ และการแสดง relic/เหรียญที่ต้องใช้ต่อหลังปิดอีเวนต์ |

สถานะชั่วคราวของฤดูกาล: season ID, Candy และบัญชีรายการรับ–ใช้, วัตถุดิบ, เวลาบ้าน, เฟสเควส, รอบเกม, แปลงและผลผลิต, ประวัติซื้อ/คราฟต์, Totem

สถานะถาวร: สิทธิ์รางวัลพร้อมที่มา, วันรับ, รหัสธุรกรรม, relic instance และข้อจำกัด/การปลดผนึก; แยกจากสิทธิ์ลองของ 23 ชิ้นใน ALT และจากสิทธิ์ลองธีมชั่วคราววันที่ 31 ตุลาคม

ธุรกรรมทุกชนิดต้องผูกบัญชีและฤดูกาล มี request ID ที่ส่งซ้ำแล้วคืนผลเดิม ตรวจยอด/เงื่อนไขก่อน แล้วบันทึกการหักของ การรับของ และเฟสใหม่เป็นชุดเดียว บันทึกไม่ได้ต้องไม่หักของบางส่วน สุ่มใหม่เพราะรีโหลดหรือ retry ไม่ได้

ตัวเก็บข้อมูลต้องเชื่อมการสลับบัญชี สำรอง คืนค่า และซิงก์ของแอปเดิม ไม่วางยอดไว้ในคีย์ global ที่บัญชีอื่นอ่านต่อได้ ไม่รวมยอด Candy แบบเลือกยอดมากสุดหรือบวกยอด snapshot สองเครื่อง เพราะทำให้ใช้ยอดเดิมซ้ำได้

ก่อนเปิดรับของจริงต้องกำหนดผู้ตัดสินธุรกรรม เวลา และการชนกันข้ามเครื่องให้ชัดเจน การทดสอบข้อมูลจำลองในเครื่องไม่ถือว่าแก้ปัญหานี้แล้ว หากต้องเพิ่มบริการภายนอก alt/ ให้วางรายละเอียดแยกเพื่อจัดขอบเขตก่อนลงมือ

## 6. ลำดับงานและเกณฑ์จบแต่ละช่วง

### ช่วง 0 — ฐานข้อมูลสเปกและบั๊กภาพ

- จัดรายการ confirmed/pending/proposed และตารางเชื่อม ID จากข้อ 4 โดยรักษาบทพูดเต็ม
- ตรวจ full-motion บนสำเนาข้อมูลจำลอง: หน้าแอปเดี่ยวเทียบ iframe, ลดภาพเทียบเต็มภาพ, ปิด/เปิดเสียง, เปิดใหม่หลัง worker reload
- เก็บจำนวน DOM, observer callbacks, animation frames, ตัวจับเวลา และงานที่กินเวลานาน เพื่อแยกสาเหตุ ไม่ถือว่าการเปลี่ยนปุ่มสำเร็จแปลว่าภาพไม่ค้าง
- เพิ่มกรณีทดสอบจากสาเหตุที่ทำซ้ำได้ แล้วแก้เฉพาะจุด; งานแกนข้อมูลเดินต่อได้ แต่ยังไม่รับรองคุณภาพภาพเต็มจนตรวจเบราว์เซอร์ผ่าน

**จบช่วง:** ข้อกำหนดไม่ขัดกันในส่วนที่ยืนยันแล้ว และมีบันทึกอาการ/หลักฐานของบั๊กภาพหรือผลแก้ที่ตรวจซ้ำได้

### ช่วง 1 — แบบหน้าอีเวนต์ให้ตรวจได้

- ทำแบบหน้าสำรวจอีเวนต์ใหม่โดยใช้ภาพและ catalog เดิม ไม่สร้างแกลเลอรีหรือต้นแบบรางวัลซ้ำ
- หน้าหลักอีเวนต์แสดงไบโอมปัจจุบัน เวลาช่วงถัดไป Candy บ้าน 5 หลัง และเควสถัดไป; เข้ากระเป๋า สวน ร้าน หม้อ และพิธีจากหน้านี้
- ทบทวนทางเข้าที่ฉัน/สำรวจจากจุด Collection เดิม ให้เด่นพอเห็นโดยไม่ทับการ์ดงานหรือทำให้หน้าแรกต้องเลื่อน ตำแหน่งจริงยังเป็นแบบเสนอ
- รองรับก่อนเปิด/เปิด/ปิด และข้อมูลที่ยังไม่กำหนดอย่างตรงไปตรงมา เกมทดสอบใช้ข้อมูลจำลองที่แยกบัญชีจริง

**จบช่วง:** มีภาพหน้าจอให้เจ้าของตรวจที่ 375×812, 820×1180 และ 1440×900 ก่อนเชื่อมการใช้ของจริง

### ช่วง 2 — ฤดูกาล กระเป๋า และธุรกรรม

- สร้างสถานะฤดูกาล/ไบโอมโดยฉีดเวลาเข้าไปทดสอบได้ ไม่ใช้เวลาเครื่องโดยไม่มีนโยบายรองรับ
- สร้างบัญชีรับ–ใช้ Candy, สต็อกวัตถุดิบ, เฟสเควส และสิทธิ์รางวัลถาวรตามสัญญาข้อมูลเดียว
- รองรับคลิกซ้ำ สองแท็บ รีโหลดกลางรายการ พื้นที่จัดเก็บเต็ม และสลับบัญชี โดยยอดไม่ติดลบและของไม่หายบางส่วน
- ค่าที่ยังไม่ยืนยันปิดเฉพาะการกระทำที่พึ่งค่านั้น ส่วน schema และการทดสอบเดินต่อได้

**จบช่วง:** รับ/ใช้ของด้วยข้อมูลจำลองสำเร็จและทำซ้ำไม่ได้ สิทธิ์ถาวรอ่านได้โดยไม่ต้องโหลด event/

### ช่วง 3 — บ้านและวงจรหาของ

- ใช้ Treat/Trick และเรทที่ยืนยันแล้วตามลำดับ Candy → โอกาสของ → ระดับ/ปลายทาง Breakthrough → รายชื่อ
- เชื่อม cooldown scope, รอบเพดาน และการจ่ายเศษหลังได้คำตอบ ไม่ให้ Totem/การเปลี่ยนไบโอมรีเซ็ตสิทธิ์โดยไม่มีข้อกำหนด
- เติม pool Vampire/Graveyard, จำนวนต่อดรอป, น้ำหนักรายชื่อ และ fallback ก่อนเปิดบ้านจริงในไบโอมนั้น; ไม่สุ่มใหม่จนกว่าจะได้ระดับที่มีของเพราะจะบิดเรท
- ทดสอบเส้นทางคนเข้า 1–2 รอบ/วันสู่ส่วนผสมโคมใน 2–3 วัน ด้วยค่าที่ระบุชัดว่าเป็นข้อเสนอหรือยืนยันแล้ว เป้าหมายนี้ยังไม่ใช่หลักฐานว่าตารางสุ่มปัจจุบันทำได้ และไม่ใช่เป้าหมายให้ได้ทุกรางวัลใน 2–3 วัน
- ถ้าไม่สอดคล้อง เสนอช่องทางช่วยที่ชัดเจนให้เจ้าของเลือก ไม่ปรับเรทบ้านหรือสร้างการันตีเอง

**จบช่วง:** บ้านไม่ข้ามเพดาน/คูลดาวน์ รับซ้ำไม่ได้ และมีผลตรวจสมดุลพร้อมข้อจำกัดที่อธิบายได้

### ช่วง 4 — เควสและเกมเป็นชุดที่เล่นจบได้

1. สร้างตัวประเมินเควสร่วมและพิสูจน์กรณีหลายเฟส, anyOf, show-only, upgrade-existing และรอวัฏจักร โดยใช้ข้อมูลจำลอง
2. ต่อ Tang Q1 และ Ghost Ship Hunt: เริ่ม 15 วินาที, ถูกครบ 6, ผิด+หมดเวลาครบ 3 กลับฝั่ง; ตารางลดเวลา ค่าซ่อม 25–50 และรางวัลกล่องรอกติกาจริง จากนั้นต่อ Q2/Q3
3. ต่อ Win Q1 ให้ Shovel, Jack Q1 เถาวัลย์และ Plot แล้วระบบปลูก/เก็บ Pumpkin พร้อมหลักฐานว่าปลูกเอง; ต่อ Jack Q2/Q3 หลังได้กติกาการใช้เครื่องมือและสวน
4. ต่อ Win Q2 ขุดให้จบและจับผีทั้งหมดใน 30 วินาที, Q3 Blade Phase, Q4 Restricted, Q5 ปลดเคียวเดิมโดยไม่หัก Dutchman's Soul
5. ต่อ Dech Q1 รับ Cruor Quill ได้ทันที, เกมจับผิดภาพ/Q2, ประตูวัฏจักรถัดไป และ Q3 เมื่อจำนวนของครบ ไม่ใช้ Totem ข้ามเงื่อนไขโดยเดา

**จบช่วง:** ทุกสายเล่นตามเฟสและบทเดิมได้ รับรางวัลเฉพาะจุดที่กำหนด สลับไบโอม/ออกแอปแล้วไม่ล้างความคืบหน้า สายที่ค่าขาดยังแสดงสถานะรอยืนยัน

### ช่วง 5 — ร้าน หม้อ พิธี และระบบเสริม

- ร้านใช้รายการขายที่กำหนดชัดเจน แยกหลักฐานซื้อจากการได้รับของช่องทางอื่น เพื่อคำนวณเหรียญซื้อครบถูกต้อง
- หม้อและพิธีใช้สูตรที่ยืนยันแล้วผ่านธุรกรรมชุดเดียวกัน ชุด Rare มาจากพิธี; ฉากอัญเชิญที่มีอยู่ใช้แสดงผลหลังธุรกรรมสำเร็จ
- กำหนดราคา เรท การันตี และเงื่อนไขธีมหลักก่อนเปิดรับของเหล่านั้น ไม่เอาเรทวัตถุดิบมาใช้เป็นเรทของตกแต่ง
- เชื่อมรางวัลทำงานจริงจากจุดที่บันทึกงานสำเร็จแล้วด้วยรหัสงาน/เหตุการณ์ กันย้อนติ๊กหรือซิงก์แล้วรับซ้ำ ไม่ใช้ haptic(done) เป็นหลักฐาน
- ต่อ NPC นิรนามสุ่ม 1–2 ตัวและ Totem หลังได้ช่วงเกิด/หาย ปริมาณของ รางวัล แหล่งหา เวลาใช้ และผลต่อ cycle/cooldown
- เรื่องชวนเพื่อนยังเป็นแนวคิดรอยืนยัน ไม่ใช้ล็อกธีมหรือแปลง 10 แต้มเป็น Candy เอง

**จบช่วง:** ทั้งสามช่องทางใช้ของถูกสูตร แยกแหล่งสิทธิ์ถูกต้อง และเหรียญอ้างรายการร้านของฤดูกาลนั้น

### ช่วง 6 — ปิดอีเวนต์และตรวจรอบเปิดจริง

- กำหนดพฤติกรรมเกม/ธุรกรรมที่กำลังค้างตรงเปลี่ยนไบโอมหรือหมดอีเวนต์ และนโยบาย Candy วัตถุดิบ Totem Plot/ผลผลิต/เควสค้างก่อนเปิดจริง ไม่ลบหรือแปลงของเอง
- ปิดการหา/รับของจากทุกช่องทางเมื่อจบ ทดสอบถอด event/ แล้วใช้ธีม ชุด ห้อง เอฟเฟกต์ relic และเหรียญที่ได้รับไปแล้วต่อได้
- ตรวจ worker reload, ออนไลน์/ออฟไลน์, การเปลี่ยนบัญชี, หลายเครื่อง และการย้อนเวลา ตามแบบแหล่งข้อมูลที่เลือก
- ตรวจงานตัวอย่างเสร็จ → เล่นเอฟเฟกต์/ข้าม → งานถัดไปครั้งเดียว, reduced motion, ปิดเสียงเริ่มต้น, แป้นพิมพ์/นิ้ว/เมาส์ และหน้าแรกไม่เลื่อนที่ 375×812
- ทำ QA ภาพเต็มในเบราว์เซอร์และบนอุปกรณ์สัมผัสจริงก่อนอ้างผลของเครื่องนั้น แยกผลวัดพื้นที่จอออกจากผลความลื่น/เสียง/สัมผัส
- ชื่อเวอร์ชันรอเจ้าของ; ถ้าเตรียมปล่อยให้ปรับเวอร์ชัน/แคช/เอกสารตามกฎครบ แล้วรอคำสั่งเผยแพร่เฉพาะรอบนั้น

## 7. คำถามที่จำเป็น แยกตามจังหวะงาน

### ก่อนทำกติกาบ้านที่รับของจริง

1. คูลดาวน์ 4 ชั่วโมงนับรายหลังแยกตามไบโอม, ทั้งชุดแยกไบโอม, หรือบ้านชุดเดียวร่วมทุกไบโอม?
2. เพดาน 300 Candy/24 ชั่วโมงใช้หน้าต่างย้อนหลัง 24 ชั่วโมง หรือรอบรีเซ็ตรายวัน? ถ้ารอบวัน ใช้เวลาใดและ timezone ใด?
3. เมื่อสิทธิ์ Candy เหลือน้อยกว่ารางวัลบ้าน จ่ายเฉพาะที่เหลือแล้วเริ่มคูลดาวน์หรือไม่? เมื่อจ่ายจริงเป็น 0 ยังสุ่มของ/เริ่มคูลดาวน์หรือไม่?

schema, แบบหน้า และการตรวจบั๊กภาพทำก่อนได้ คำตอบเหล่านี้ไม่ต้องใช้เป็นเหตุหยุดทุกส่วน

### ก่อนต่อส่วนที่พึ่งค่าที่ยังว่าง

- แหล่ง/ระดับของใหม่และ pool ที่ยังไม่ครบ, จำนวนดรอป/น้ำหนักรายชื่อ/fallback
- จำนวนของ Dech Q2/Q3; Shovel ถูกหักใน Jack Q2 หรือเป็นเพียงการตรวจว่ามี และวิธีหาเพิ่มหากใช้หมด
- ระยะโต ผลผลิต เมล็ด การรดน้ำ/จำนวนแปลง; รายละเอียดเกมและรางวัลที่ยังไม่กำหนด
- สูตร/ราคา/การันตีและรายการนับซื้อครบ; เงื่อนไขธีมหลัก; Totem/cycle; รางวัลทำงานและ NPC สุ่ม

### ก่อนเปิดกิจกรรมจริง

- วันเวลาเริ่ม–จบสองสัปดาห์ ความสัมพันธ์กับวันลอง 31 ตุลาคม timezone และรอยต่อทั้ง 4 ช่วง
- แหล่งตัดสินเวลาและธุรกรรม นโยบายออฟไลน์/ข้ามเครื่อง และการปิดอีเวนต์ระหว่างเล่น
- นโยบาย Candy/วัตถุดิบ/แปลง/เควสค้างหลังปิด ส่วนสิทธิ์รางวัลที่ได้รับแล้วถาวรเป็นข้อยืนยันเดิม

## 8. งานชุดแรกที่ทำต่อจากแผนนี้ได้

ตรวจ remote อีกครั้งเมื่อเครือข่ายพร้อม → จัด metadata/ตารางเชื่อม ID และบันทึก confirmed/pending → ทำแบบหน้าอีเวนต์ให้ตรวจได้ พร้อมตรวจซ้ำบั๊ก full-motion → สร้างกระเป๋า/ธุรกรรมด้วยข้อมูลจำลอง → ต่อบ้านหลังตอบคำถามเฉพาะกติกาบ้านครบ

ยังคง claimingEnabled:false จนระบบที่เปิดใช้จริงมีข้อมูลครบและผ่านการตรวจตามขอบเขต ไม่ถือว่าการผ่านชุดตรวจ 27 ข้อเดิมเป็นการอนุมัติเปิดระบบเศรษฐกิจใหม่
