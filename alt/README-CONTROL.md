## ติดตั้ง (ทำครั้งเดียว)

### 1. รัน migration

```
supabase/migrations/20260912120000_app_config.sql
```

เอาไปวางใน **Supabase → SQL Editor → Run** (หรือ `supabase db push` ถ้าใช้ CLI)

สร้างให้สี่อย่าง:

| ของ | หน้าที่ |
|---|---|
| `app_admins` | ใครแก้ค่าตั้งได้ · **ไม่มี policy ให้เขียนจาก client เลย** |
| `app_config` | ค่าตั้งก้อนเดียว (jsonb) · **ทุกคนอ่านได้** แอดมินเท่านั้นที่เขียนได้ |
| `app_config_versions` | ประวัติทุกครั้งที่เผยแพร่ · trigger เขียนให้เอง |
| `admin_stats()` | ยอดรวมสำหรับหน้า Analytics · คืน `null` ถ้าไม่ใช่แอดมิน |

### 2. ตั้งแอดมินคนแรก

หา user id ที่ **Authentication → Users** แล้วรันใน SQL Editor:

```sql
insert into public.app_admins (user_id, note)
values ('<UUID ของคุณ>', 'เจ้าของระบบ');
```

> เปิดให้เพิ่มแอดมินจากหน้าเว็บไม่ได้ เพราะ anon key อยู่ในโค้ดฝั่งเบราว์เซอร์ —
> ใครก็ตามที่เปิดแอปได้จะเลื่อนตัวเองเป็นแอดมินได้ทันที

### 3. เปิด `/alt/control.html` แล้วล็อกอิน

ถ้ายังไม่ได้เป็นแอดมิน หน้าจะบอกและพิมพ์คำสั่ง SQL พร้อม UUID ของคุณมาให้ก๊อป

## พรีวิวคือแอปจริง ไม่ใช่ภาพวาดของแอป

Home Builder · Theme Studio · Content Manager · Feature Manager มี `index.html` ตัวจริง
ฝังอยู่ใน `<iframe>` ข้าง ๆ — ลากบล็อก เปลี่ยนสี ปิดฟีเจอร์ แล้ว **หน้าแรกจริงพร้อมงานจริง
ของคุณ** วาดใหม่ทันที โดยยังไม่มีใครนอกจากคุณเห็น

```
control.js ──postMessage({type:'sos-preview-config'})──▶ iframe
                                                          │
                                    remote-config.js (โหมดพรีวิว)
                                                          │
                                          announce() → renderAll()
```

**สามข้อที่โหมดพรีวิวต่างจากปกติ และทั้งสามข้อจำเป็น**

1. ไม่โหลดจากเซิร์ฟเวอร์ — ต้องเห็นค่าที่กำลังลาก ไม่ใช่ค่าที่เผยแพร่แล้ว
2. **ไม่เขียนแคชเด็ดขาด** — iframe ใช้ `localStorage` ก้อนเดียวกับแอปจริงของคนที่เปิดอยู่
   (โดเมนเดียวกัน) เผลอเขียนเมื่อไหร่ ค่าที่ยังลากเล่นอยู่จะกลายเป็นค่าจริงบนเครื่องเขาทันที
3. ไม่ฟัง `visibilitychange` — ไม่งั้นสลับแท็บกลับมาแล้วค่าที่ลากไว้ถูกทับ

**สัญญาณบอกว่าเป็นพรีวิวคือธงบนหน้าแม่ (`window.parent.__SOS_CONTROL_PREVIEW__`)
ไม่ใช่คิวรีสตริง** — `app.js` ลบคิวรีทิ้งตอนบูต แล้วพอ service worker เข้าคุมครั้งแรก
มันสั่ง `location.reload()` ด้วย URL ที่ถูกลบไปแล้ว พรีวิวจะกลายเป็นแอปธรรมดาเงียบ ๆ
แล้วเริ่มเขียนแคชทับค่าจริง · คิวรียังใส่ไว้เป็นตัวสำรอง แต่เชื่อไม่ได้ตัวเดียว

## แก้ UI ด้วยมือแล้วเผยแพร่ให้ทุกคน

ในกรอบพรีวิวมีปุ่ม **"แก้ดีไซน์"** มุมขวาบน (คือ `visual-editor.js` ที่มีอยู่แล้วในโปรเจกต์
แต่เดิมถูกปิดไว้) — แตะชิ้นไหนก็ได้ในแอปแล้วปรับสี · ขนาด · ความมน · ระยะห่าง ·
แก้ข้อความ พร้อม undo/time-travel ของมันเอง

**สิ่งที่เปลี่ยนไปคือปลายทาง** เดิมมันเก็บลง `localStorage` ของเครื่องเดียว — สวยอยู่คนเดียว
ตอนนี้ผลลัพธ์ไหลกลับมาเป็น `ui` ในค่าตั้ง แล้วกดเผยแพร่ทีเดียวถึงทุกเครื่อง

```
ui: {
  rules:  { 'ตัวเลือก CSS': { prop: value } },   // ทับสไตล์ (ใส่ !important ให้เอง)
  tokens: { 'ชื่อธีม': { '--var': value } },      // ทับโทเคนเฉพาะธีมนั้น
  texts:  { 'ตัวเลือก CSS': 'ข้อความใหม่' }
}
```

`visual-editor.js` โหลดเฉพาะในกรอบพรีวิวเท่านั้น — ไฟล์มัน ~50KB และเด็กไม่เคยต้องใช้
(ตรวจแล้ว: บนแอปจริง `window.sosVE` เป็น `undefined`)

### ข้อจำกัดที่ต้องรู้ ไม่ใช่บั๊ก

- **แก้ข้อความได้เฉพาะชิ้นที่เป็นข้อความล้วน** — ชิ้นที่มีไอคอนอยู่ข้างใน (เช่น `.td-more`
  ที่มี `<svg>` ต่อท้าย) ถูกข้ามโดยตั้งใจ ไม่งั้นเขียนทับแล้วไอคอนหายทั้งกิ่ง
  ข้อความพวกนั้นใช้ Content Manager แทน ซึ่งแก้ตอนวาด ไม่ใช่ตอนทับทีหลัง
- **ตัวเลือกแบบเจาะจงชิ้นเดียว (`nth-of-type`) เปราะ** — แอปเขียนทับ `innerHTML` ทั้งก้อน
  ทุกครั้งที่วาดใหม่ · ถ้าจะให้ทน ใช้โหมด "แก้พร้อมกัน" ของตัวแก้ดีไซน์ซึ่งยึดตามคลาส
- **ย้ายตำแหน่งชิ้นส่วนอิสระแบบ Canva ทำไม่ได้** — สิ่งที่ทำได้คือสไตล์ · ขนาด · ระยะ ·
  สี · ข้อความ · ซ่อน · และลำดับบล็อกหน้าแรก (ผ่าน Home Builder)
  การลากชิ้นไปวางที่ไหนก็ได้บนเลย์เอาต์จริงจะพังบนจอขนาดอื่นทันที

## ค่าตั้งเดินทางยังไง

```
Control Center  ──เผยแพร่──▶  app_config (Supabase)
                                   │
                                   │ อ่านตอนเปิดแอป + ทุกครั้งที่กลับมาหน้าจอ
                                   ▼
                          remote-config.js  ──▶  window.SOSCFG
                                   │
             ┌─────────────────────┼──────────────────────┐
             ▼                     ▼                      ▼
      prioWeight()           sosFeature()            sosText()
      (engine.js)            (app.js)                (app.js)
```

**สามข้อที่ `remote-config.js` ห้ามละเมิด**

1. **ค่าเริ่มต้นอยู่ในไฟล์ และต้องให้ผลเหมือนแอปทุกวันนี้เป๊ะ**
   เซิร์ฟเวอร์ล่ม · ยังไม่ได้ตั้งอะไร · เพิ่งลงครั้งแรก → แอปต้องเหมือนเดิม
   *(พิสูจน์แล้ว: สไลเดอร์ทั้งหกตัวที่ค่าเริ่มต้นให้ตัวคูณ = 1.0 พอดี)*
2. **อ่านค่าได้ทันทีแบบ synchronous** — ไม่มีทางที่จอจะค้างเพราะรอค่าตั้ง
3. **แคชลงเครื่อง** — เปิดครั้งต่อไปได้ค่าล่าสุดตั้งแต่เฟรมแรก แล้วค่อยอัปเดตเงียบ ๆ

คีย์แคช: `studentos.alt.remoteConfig` — **คีย์ใหม่ ไม่ทับของเดิม ล้างทิ้งได้เสมอ**

## ต่อสายแล้วจริง ๆ กับยังไม่ได้ต่อ

### ✅ ฝั่งแอป — เห็นผลทันทีที่เปิดแอปรอบถัดไป

| หน้า | ต่อเข้ากับ |
|---|---|
| **Home Builder** | `HOME_BLOCKS` / `homeLayout()` ใน `app.js` — `renderMenu()` วาดตามลำดับนี้ |
| **Priority Engine** | `pw()` ใน `engine.js` — คูณเข้ากับเลขดิบทุกจุดใน `priorityInfo()` |
| **Theme Studio** | ฉีด CSS custom property ทับ `:root` (สี · ความมน · เงา · ระยะ · ฟอนต์ · ขนาดฐาน) |
| **Content Manager** | `sosText()` — สามจุดที่ต่อไว้: `askPh` · `railTitle` · `toolsLink` |
| **Feature Manager** | `sosFeature()` — `ocr` · `social` · `ttscan` · `shop` |
| **เส้นบันทึกเอง + สวิตช์** | `autoAcceptBar()` / `autoAcceptOn()` ใน `inbox.js` (ขั้นต่ำล็อกที่ 50%) |
| **Analytics** | `admin_stats()` — ยอดรวมจริง ไม่มีแถวของใครหลุดออกมา |
| **ประวัติเวอร์ชัน** | `app_config_versions` — ย้อนกลับได้ทุกเวอร์ชัน |

### ✅ ฝั่งเซิร์ฟเวอร์ — มีผลภายใน 1 นาทีหลังเผยแพร่

ทุกฟังก์ชันอ่านผ่าน `_shared/appconfig.ts` ซึ่งแคช 60 วินาที และ **ไม่เคยโยน error** —
อ่านไม่ได้เมื่อไหร่ = ใช้ค่าคงที่ในไฟล์นั้นต่อ

| หน้า | ต่อเข้ากับ |
|---|---|
| **AI Brain** | `ask-sai` — พรอมป์ · กติกา (ต่อท้ายพรอมป์) · temperature · เพดานโทเคน |
| **Notification Center** | `send-reminders` — เตือนก่อนสอบกี่วัน · สวิตช์รายประเภท · เวลาส่ง · เวลาห้ามเตือน · ข้อความ |
| **OCR Center** | `ocr-assist` — เพดานเวลา (คูณลงบนอัตราส่วนเดิมของแต่ละผู้ให้บริการ) · จำนวนรอบลองใหม่ |

**ต้อง deploy ก่อนถึงจะมีผล:**

```bash
npx supabase functions deploy ask-sai ocr-assist send-reminders
```

### ⬜ บันทึกค่าไว้แล้ว แต่ยังไม่มีผล

ทั้งหมดนี้มีป้ายเตือนอยู่บนหน้าจอของมันเอง และรวมอยู่บน Dashboard

| ของ | ติดตรงไหน |
|---|---|
| **เพดานคำถามต่อคนต่อวัน** | `ask-sai` ไม่ได้อ่านว่าใครถาม (แอปยิงด้วย anon key) · คนที่ยังไม่ล็อกอินนับไม่ได้เลย ต้องมีตารางนับก่อน |
| **เลือกผู้ให้บริการ AI / OCR** | ผูกกับ secret `ASK_PROVIDER` / `OCR_PROVIDER` — เปลี่ยนจากหน้าเว็บแล้วกุญแจไม่ตามไปด้วย |
| **สรุปแผนตอนเช้า · เตือนก่อนสตรีคขาด** | ยังไม่มีตัวส่งสองแบบนี้ใน `send-reminders` |
| **เก็บรูปต้นฉบับ (OCR)** | ยังไม่มีที่เก็บ |
| **A/B Testing** | แบ่งกลุ่มได้ แต่ไม่มีตารางเก็บ event จึงวัดผลไม่ได้ |
| ฟีเจอร์ `cloud` `wheel` `line` | ทางเข้ากระจายหลายที่ · ต้องกันฝั่งเซิร์ฟเวอร์ด้วย |

## วิธีต่อสายเพิ่ม

### เพิ่มข้อความที่แก้ได้จากหน้าเว็บ

1. ใน `app.js` เปลี่ยน `'ข้อความเดิม'` เป็น `sosText('ชื่อ', 'ข้อความเดิม')`
2. ใน `control.js` เพิ่มแถวลง `TEXT_META`

> **ห้ามเพิ่มใน `TEXT_META` โดยไม่ทำข้อ 1** — ช่องที่แก้แล้วไม่มีอะไรเปลี่ยน
> ทำให้เลิกเชื่อทั้งหน้า ไม่ใช่แค่ช่องนั้น

### เพิ่มบล็อกใหม่บนหน้าแรก

1. เขียนฟังก์ชันที่คืน HTML
2. เพิ่มลง `HOME_BLOCKS` และ `HOME_ORDER` ใน `app.js`
3. เพิ่มลง `DEFAULTS.home.blocks` ใน `remote-config.js`
4. เพิ่มป้ายลง `BLOCK_META` + `BLOCK_PV` ใน `control.js`

บล็อกใหม่จะโผล่เองกับทุกคน **แม้กับคนที่เคยจัดหน้าแรกไว้แล้ว** (ดู `homeLayout()`)

### ให้ Edge Function อีกตัวอ่านค่าตั้ง

```ts
import { appConfig, num, str, fill } from '../_shared/appconfig.ts';

const c = await appConfig();                  // แคช 60 วิ · ไม่เคยโยน error · ไม่รอเกิน 3 วิ
const prompt = str(c.ai?.prompt, DEFAULT_PROMPT);   // ว่าง → ค่าเดิม
const secs   = num(c.ocr?.timeout, 20, 3, 60);      // นอกช่วง → ค่าเดิม
const msg    = fill(tplText, { task: 'ใบงาน', days: 3 });
```

**`num` / `str` มีไว้เพื่อบังคับข้อเดียว:** ทุกจุดที่อ่านค่าตั้งต้องมีค่าเริ่มต้นติดอยู่เสมอ
เขียน `c.ai.prompt` เปล่า ๆ ที่ไหนเมื่อไหร่ ฟังก์ชันนั้นจะพังในวันที่ยังไม่มีใครตั้งค่า

## กับดักที่รู้อยู่แล้ว

- **ขีดแบ่งดาว** (52/44/32/22 ใน `engine.js`) ตั้งจากเพดานคะแนน ≈95 ของน้ำหนักชุดเริ่มต้น
  ดันน้ำหนักขึ้นทั้งกระดาน → ป้าย "ด่วนมาก" ติดครึ่งรายการ = ป้ายที่ไม่ได้บอกอะไร
- **เส้น OCR 80%** ต่ำกว่านี้แปลว่างานที่อ่านผิดไหลเข้าแผนเองเงียบ ๆ
- **หน้า Control Center ใช้โทเคนสีแยกชุด** (`--c*`) ตั้งสีแอปพลาดแล้วยังเข้ามาแก้คืนได้
- **"แก้" กับ "เผยแพร่" เป็นคนละก้าว** — ลากสไลเดอร์ไม่ได้เปลี่ยนแอปของใครจนกว่าจะกดเผยแพร่
- **`scr-menu` คือหน้าแรก** ส่วน `scr-home` คือรายการงาน (ชื่อสวนทางกันมาตั้งแต่ 1A8)
