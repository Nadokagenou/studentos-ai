# StudentOS AI — เวอร์ชัน **ALT** (Sandbox)

> บิลด์นี้ **ไม่ใช่ตัวที่ปล่อยจริง** — เป็นรุ่นไว้ทดลองฟีเจอร์ใหม่
> ตัวจริงอยู่ที่ https://nadokagenou.github.io/studentos-ai/

โฟลเดอร์ `alt/` คือแอปตัวเต็มที่รวมไฟล์จริงทั้งชุดมาไว้ที่เดียว
(`index.html` + `style.css` + `engine.js` + `app.js` + `config.js` + `sw.js` + `manifest.json` + ไอคอน)
แล้วติดป้ายว่าเป็นรุ่น ALT ทุกจุดที่คนใช้จะเห็น

## เปิดดู

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "serve-alt.ps1"
```

แล้วเปิด http://localhost:8788/ (สคริปต์อยู่ที่โฟลเดอร์แม่ · มี `.claude/launch.json` ตั้งไว้ให้แล้วชื่อ `studentos-alt`)

เครื่องนี้ไม่มี node/python จึงเสิร์ฟด้วย `System.Net.HttpListener` ของ .NET แทน —
ต้องเปิดผ่าน http เท่านั้น เพราะ OCR (Tesseract) และ service worker ใช้ `file://` ไม่ได้

## ต่างจากตัวจริงตรงไหน

| จุด | ตัวจริง | ALT |
|---|---|---|
| `APP_VERSION` (app.js) | `v35` | `v35-ALT` + `APP_CHANNEL = 'ALT'` |
| ข้อมูลใน localStorage | `studentos.v1` | `studentos.alt.v1` |
| ธีม / skipLogin / installGuide | `studentos.*` | `studentos.alt.*` |
| service worker cache (sw.js) | `studentos-v35` | `studentos-alt-v35` |
| ชื่อใน manifest.json | StudentOS AI | StudentOS AI · ALT |
| `<title>` + meta | ปกติ | + `robots: noindex` (กันโดน index ปนตัวจริง) |
| ป้ายบนหน้าจอ | — | ป้าย `ALT` มุมขวาบน · บรรทัดบอกรุ่นในหน้า login · คำว่า ALT บน splash · หมายเหตุใต้เครื่อง |

**สำคัญ:** คีย์ localStorage แยกกันหมด → เล่นฟีเจอร์ใน ALT ยังไงก็ไม่กระทบข้อมูลของตัวจริง
(กลับกัน ALT ก็ไม่เห็นงานที่เคยเพิ่มไว้ในตัวจริง — กด "โหลดข้อมูลตัวอย่าง" ในแท็บ **ฉัน** ได้)

## ฟีเจอร์ทดลองที่มีเฉพาะใน ALT

### 1. ปัดการ์ดงานในหน้าแรก
- **ปัดขวา = ทำเสร็จ** → ใช้ `toggleDone()` ตัวเดิม ได้เอฟเฟกต์ฉลอง + toast ครบ
- **ปัดซ้าย = เลื่อนไปพรุ่งนี้** → `snoozeToTomorrow()` คงเวลาเดิมของวันไว้
  งานที่กำหนดส่งเลยพรุ่งนี้ไปแล้ว จะเลื่อนออกอีก 1 วันจากกำหนดเดิมแทน (ไม่งั้นการปัดจะกลายเป็นเร่งงานให้เร็วขึ้น)
  พร้อมปุ่ม **เลิกทำ** ใน toast · ล้าง `remindedAt` ให้เตือนใหม่ได้ตามกำหนดใหม่
- ปัดไม่ถึง 76px = ดีดกลับ · ถึงระยะแล้วเครื่องสั่นสั้น ๆ บอกว่าปล่อยได้
- แตะเฉย ๆ ยังเปิดฟอร์มแก้ไขเหมือนเดิม · ปุ่มติ๊กกลมด้านขวายังกดได้ตามปกติ
- ทำด้วย Pointer Events ตัวเดียว ใช้ได้ทั้งนิ้วและเมาส์ · `touch-action:pan-y` ให้เลื่อนจอแนวตั้งได้ปกติ
- โค้ดอยู่ที่ `app.js` หัวข้อ `ALT: ปัดการ์ดงานในหน้าแรก` + `alt.css` หัวข้อ `ปัดการ์ดงาน`
  ตัวฟัง event เกาะที่ `#homeBody` ครั้งเดียว (ไม่ใช่ที่การ์ด) จึงอยู่รอดทุกครั้งที่ `renderHome` เขียนทับ innerHTML
- การกัน click หลังปัดใช้ "เวลาที่เพิ่งปัดจบ" (400ms) ไม่ใช่ธงค้างไว้ — บนมือถือการปัดมักไม่มี click ตามมาเลย
  ถ้าใช้ธง มันจะไปกินการแตะครั้งถัดไปแทน

### 2. งานที่เลื่อนแล้วต้องไม่หายจากหน้าแรก
หน้าแรกโชว์ 3 อันดับแรกของ AI — พอปัดเลื่อน ลำดับจะตกทันทีจนหลุดออกนอก 3 อันดับ คนปัดจะรู้สึกว่า "งานหายไป"
ตอนนี้หน้าแรกจึงโชว์ **3 อันดับแรก + งานที่ถูกเลื่อนไว้ (สูงสุด 3 งาน)** ใต้หัวข้อ *เลื่อนไว้ — ยังอยู่ในแผน*
โดยเลขบนการ์ดยังเป็นลำดับจริงของงานนั้น (เช่นขึ้นเลข 4) — ยังอยู่ แค่ถูกเลื่อน

### 3. ป้าย "เลื่อน"
งานที่ถูกปัดเลื่อนจะมีป้ายสีเหลืองข้างป้ายความสำคัญ ทั้งในหน้าแรกและแท็บ **งาน**
เลื่อนซ้ำจะมีตัวเลขต่อท้าย (`เลื่อน ×3`) — เป็นสัญญาณว่ากำลังผัดวันประกันพรุ่งกับงานนี้
ตั้งกำหนดส่งใหม่เองในฟอร์มเมื่อไหร่ ป้ายจะหายไป (ถือว่าตัดสินใจใหม่แล้ว)
เก็บสถานะที่ `t.snoozedAt` + `t.snoozeCount`

### 4. วันที่ไม่มีงานค้าง = โอกาสให้รู้สึกดี
แทนที่จะเป็นจอว่าง หน้าแรกจะพูดกับผู้ใช้ว่าที่ว่างเพราะเคลียร์หมดแล้ว:
ข้อความให้กำลังใจ (สุ่มแบบคงที่ต่อวัน ไม่กระพริบเวลาเปิดซ้ำ) + ป้าย *วันนี้ติ๊กไปแล้ว N งาน* + ทางลัดไปดูงานที่ทำเสร็จ
มีสองชุดข้อความ: เคลียร์หมดแล้ว (`CLEARED_COPY`) กับยังไม่เคยมีงาน (`FRESH_COPY`)

### 5. หน้าโหลดมีเปอร์เซ็นต์จริง
`SPLASH_MIN = 3600ms` และเปอร์เซ็นต์ที่โชว์ = **min(งานที่เสร็จจริง, เวลาที่ผ่านไป / เวลาขั้นต่ำ)**
- ติดเพดานที่งานจริง → ไม่โกหกว่า 100% ทั้งที่ยังโหลดไม่เสร็จ (เน็ตช้าจะเห็นตัวเลขค้างรอจริง ๆ)
- ติดเพดานที่เวลา → ไม่กระโดดถึง 100 ใน 0.2 วิ แล้วค้างเฉย ๆ
- ป้ายใต้แถบบอกว่ากำลังทำขั้นไหน: เตรียมหน้าจอ → อ่านข้อมูลในเครื่อง → เตรียมธีมและฟอนต์ → เชื่อมบัญชี → ตรวจการแจ้งเตือน → จัดลำดับงาน
- ตัวนับเริ่มตั้งแต่บรรทัดแรกของ `initApp` (ไม่งั้นเน็ตช้าจะเห็น 0% ค้าง) และตัวเลขไม่เดินถอยหลัง
- รอฟอนต์ไทยจาก CDN ด้วย `document.fonts.ready` แต่ไม่เกิน 2.5 วิ แล้วไปต่อด้วยฟอนต์ระบบ
- บิลด์นี้ทิ้งเวลาบูตไว้ใน console (`[ALT] splash 3860ms · ขั้นที่เสร็จ 6/6`) จะได้รู้ว่าไปติดที่เวลาหรือที่งานจริง

### 6. ทำความรู้จักผู้ใช้ (หน้าเดียวจบ)
เปิดครั้งแรกหลังผ่านหน้าบัญชี → ถาม 2 อย่างที่ AI ต้องใช้จริง: **ชื่อที่อยากให้เรียก** + **เวลาว่างต่อวัน**
(แถบเลื่อน 0.5–8 ชม. พร้อมชิปลัด 1/2/3/4) · ชื่อว่างไม่ผ่าน (ทั้งแอปเรียกชื่อนี้ต่อ) · กด "ข้ามไปก่อน" ได้ ไม่ถามซ้ำ
บันทึกลง `state.settings` เหมือนที่แท็บ **ฉัน** ใช้ — แก้ทีหลังได้ที่เดิม
เสร็จแล้วขึ้นฉาก **"ยินดีที่ได้รู้จัก ___"** 2.3 วิ แล้วเข้าแอปพร้อม toast ทักทาย
ฟังก์ชัน: `routeStart()` / `routeAfterLogin()` / `openOnboard()` / `finishOnboard()` / `showWelcome()`

### 7. ทั้งแอปเรียกชื่อผู้ใช้
`who()` คืนชื่อที่บันทึกไว้ ใช้ใน: คำทักทายหน้าแรก · ประโยคของ AI (`aiGreeting` ใน engine.js) ·
คำชมตอนติ๊กเสร็จ (`celebrateCopy`) · คำเตือน (`reminderCopy`) · หน้าไม่มีงาน (`CLEARED_COPY` / `FRESH_COPY`)
ถ้ากดข้ามไม่บอกชื่อ ทุกประโยคจะตัดคำเรียกทิ้งแล้วยังอ่านรู้เรื่องเหมือนเดิม

### 8. สั่นตอบมือตอนติ๊กงานเสร็จ
`haptic()` ใน `app.js` — ติ๊กเสร็จได้จังหวะคู่ `[14, 38, 24]` (ติ๊ก—ตึง) ให้รู้สึกเหมือน "เช็คสำเร็จ"
ปัดถึงระยะ = `8` สั้น ๆ · เลื่อนงาน = `[10, 30, 10]` · ใช้กับทุกทางที่ติ๊กงานเสร็จ (ทั้งปุ่มกลมและการปัด)
