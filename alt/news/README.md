# ข่าวสารจากทีมพัฒนา

ประกาศถึงผู้ใช้ (ฟีเจอร์ใหม่ · ธีมใหม่ · อัปเดตแอป) ที่ขึ้นในจอ **"ข่าวสาร"** ของแอป
(แท็บ "ฉัน" → ข่าวสารจากทีม) — **แยกจากการแจ้งเตือนงานโดยตั้งใจ**: ไม่นับบนกระดิ่ง ไม่ขึ้นหน้าแรก
เพราะข่าวจากทีมไม่ได้ขอให้นักเรียนตัดสินใจอะไร

| ไฟล์ | คืออะไร | แอปโหลดไหม |
|---|---|---|
| `announcements.json` | ประกาศที่ผู้ใช้เห็นจริง | โหลด (`news.js`) |
| `drafts.json` | ร่างที่ AI เสนอ รอเจ้าของอนุมัติ | ไม่โหลด — ยกเว้นเปิดแอปด้วย `?newsDraft=1` เพื่อดูหน้าตาจริงก่อนอนุมัติ |
| `../devtools/news.mjs` | ตัวรวมหลักฐาน + ตัวตรวจ | ไม่โหลด |
| `../news.js` | จอข่าวสารในแอป | โหลด |

เพิ่มประกาศ **ไม่ต้องขึ้นเลขรุ่นแอป** — แก้ JSON แล้ว push ผู้ใช้ก็เห็นเลย (service worker ดึงไฟล์แบบ network-first)

**ไฟล์ข่าวมีสองที่ ต้องตรงกัน** — ตั้งแต่ 21 ต.ค. 69 แอปหลัก (ราก = เว็บจริง) อ่าน `news/announcements.json` ของตัวเอง
ส่วน ALT อ่าน `alt/news/announcements.json` · แก้ที่ `alt/` ก่อน (ตัวตรวจและ Discord อ่านไฟล์นี้) แล้วก๊อป `items` ไปไฟล์ราก
· `news.mjs check` ล้มถ้ารายการ id สองไฟล์ไม่ตรงกัน · ลิงก์ใน Discord พาไปแอปหลัก

---

## ขั้นตอน (AI ทำ 1–4 · เจ้าของทำ 5)

1. **รวมหลักฐาน** ของรุ่นที่จะประกาศ
   ```
   node alt/devtools/news.mjs evidence 1C57 > หลักฐาน.md
   ```
   ได้: แพตช์โน้ตของรุ่น · คอมมิตในช่วงรุ่น · ไฟล์ที่เปลี่ยน · บรรทัดที่บอกว่า "ยังไม่ …"
2. **อ่านแล้วคัด** — ประกาศเฉพาะสิ่งที่ผู้ใช้ *เห็นหรือใช้ได้แล้ว* บนเว็บจริง
3. **ร่างลง `drafts.json`** ภาษาไทยที่นักเรียน ม.ต้นอ่านรู้เรื่อง (ดูกติกาข้างล่าง)
4. **ตรวจ** — ต้องผ่านก่อนส่งให้เจ้าของดู
   ```
   node alt/devtools/news.mjs check
   ```
5. **เจ้าของอนุมัติ** — เปิด `/alt/?newsDraft=1` ดูหน้าตาจริง → ย้ายชิ้นที่อนุมัติจาก `drafts.json`
   ไป `announcements.json` → `check` อีกรอบ → commit → push (push = ขึ้นเว็บจริงทันที)

## ส่งต่อให้ tester ใน Discord อัตโนมัติ

push ขึ้น main แล้ว `announcements.json` เปลี่ยน → GitHub Action `.github/workflows/news-discord.yml`
ส่ง **เฉพาะข่าว id ใหม่** เข้าช่อง Discord ด้วยข้อความเดียวกับในแอป (ไม่ส่ง `evidence` · ข้ามประกาศที่เลย `until` แล้ว)

- ตั้งค่าครั้งเดียว: GitHub → Settings → Secrets and variables → Actions → secret ชื่อ `DISCORD_WEBHOOK_URL`
  (Discord: ตั้งค่าช่อง → Integrations → Webhooks → New Webhook → Copy URL) · **ห้ามใส่ URL ลงไฟล์ใน repo**
- **ลืมใส่ webhook ก่อน merge:** งานใน Actions จะขึ้นสีแดง → ใส่ secret → เปิดงานสีแดงนั้นแล้วกด **Re-run jobs**
  (รันซ้ำใช้คอมมิตเดิม จึงส่งข่าวชุดเดิมพอดี ไม่ต้องจำ id)
- ส่งข่าวเก่าซ้ำ: แท็บ Actions → news-discord → Run workflow → ใส่ id หลายตัวคั่นด้วยจุลภาค หรือเลขรุ่น (`1C60` = ทุกข่าวของรุ่นนั้น)
- ดูหน้าตาก่อนส่ง: `node alt/devtools/news-discord.mjs - alt/news/announcements.json` ไม่ส่งอะไร ·
  `node alt/devtools/news-discord.mjs --id <id> alt/news/announcements.json --dry` พิมพ์ข้อความที่จะส่ง
- เทสต์: `node --test alt/devtools/news-discord.test.mjs`

**โปรโมท + รูป** (ไม่บังคับ · ส่งไป Discord เท่านั้น แอปไม่แสดง):

- `promo` — พาดหัวชวนลอง 4–100 ตัวอักษร ขึ้นเป็นหัวใหญ่ของการ์ด (หัวข้อเดิมเลื่อนลงเป็นบรรทัดหนาแรก)
  **ต้องมี evidence ที่ `for` ชี้มาที่ `"promo"` เหมือนช่องอื่น** และห้ามคำสัญญาอนาคต — โปรโมทได้ แต่แต่งไม่ได้
- `image` — `"img/<ชื่อไฟล์>.png"` (png · jpg · webp · gif · ไม่เกิน 2 MB) วางไฟล์ไว้ที่ `alt/news/img/`
  ภาพหน้าจอแนะนำขนาด 375×812 ตัวตรวจล้มถ้าไม่มีไฟล์
- **ถ่ายภาพหน้าจออัตโนมัติ** (ข้อมูลจำลอง ไม่เชื่อมบัญชีจริง · ต้องมี Playwright):
  ```
  node alt/devtools/news-shot.mjs 1c60-news scr-news --theme=halloween
  ```
  → `alt/news/img/1c60-news.png` (375×812 คมชัด 2 เท่า) · ไม่ใส่จอ = หน้าแรก · ธีม: light dark galaxy magic halloween
  ตัวเลือก: `--open=<CSS>` เปิดส่วนที่พับ · `--scroll=<CSS>` เลื่อนไปหา · `--call=openDaySheet` เปิดแผ่น · `--clip=<CSS>` ตัดเฉพาะชิ้นนั้น
  นาฬิกาข้อมูลจำลองคือ 20 ต.ค. 69 — ป้ายอีเวนต์/นับถอยหลังบนหน้าแรกจะผิดวัน ใช้ `--clip` ตัดออก
  ตัวอย่างจริง (1C60): `news-shot.mjs 1c60-school-break scr-context --open='.cx2-sec[data-k=brk]' --scroll='.cx2-sec[data-k=brk]' --clip=.cx2-list` · `news-shot.mjs 1c60-today-line --call=openDaySheet --tap='#daySheet .dc-chips button:nth-child(2)' --clip='#scr-menu .td-railwrap'`
  ข้อมูลจำลองมีแค่งาน 4 ชิ้น — จอที่ต้องมีข้อมูลอื่น (แจ้งเตือน · แชท · เพื่อน) จะออกมาว่าง **เปิดดูภาพก่อนใช้ทุกครั้ง**
- ข้อความนำทุกครั้ง: ชวนเปิดแอป + ชวนแจ้งบั๊กในห้อง (ไม่อ้างอะไรเกินข่าวที่ตรวจแล้ว)


## กติกาเนื้อหา — ห้ามแต่ง

- **ทุกช่องที่ผู้ใช้อ่าน** (`title` · `body` · ทุกข้อใน `points`) ต้องมี `evidence` อย่างน้อยหนึ่งชิ้น
  ที่ `for` ชี้มาที่ช่องนั้น และ `quote` ต้องยกมา **ตรงตัว** จาก
  - `"patchnotes"` = แพตช์โน้ตของรุ่นใน `release` เท่านั้น (ยกข้ามรุ่นไม่ได้) หรือ
  - `"commit:<sha>"` = ข้อความคอมมิตนั้น
  ตัวตรวจเทียบแบบไม่สนตัวหนา/backtick/ช่องว่าง แต่คำต้องตรง
- **ห้ามประกาศ** ของที่แพตช์โน้ตบอกว่า "ยังไม่ได้รัน / ยังไม่เปิด / รอเจ้าของ / ยังค้าง"
  ตัวอย่างจริงจาก 1C57: เมนูแชท "ตอบกลับ · แก้ไข · ปักหมุด · ปฏิกิริยา" ต้องรันไฟล์ฐานข้อมูลก่อน
  และแพตช์โน้ตบอกว่ายังไม่ได้รัน → ประกาศได้แค่ คัดลอก · ส่งต่อ · ยกเลิกการส่ง
- **ห้ามคำสัญญาอนาคต** — "เร็ว ๆ นี้" "กำลังจะมา" "เตรียมพบ" "ในอนาคต" ฯลฯ ตัวตรวจไม่ให้ผ่าน
- **ห้ามพูดชื่อไฟล์ ชื่อฟังก์ชัน ชื่อไลบรารี** (React Bits · Supabase · `inbox.js`) — ผู้ใช้ไม่รู้จัก
- **บอกผลที่ผู้ใช้ได้** ไม่ใช่สิ่งที่ทีมทำ: "กดแล้วเปิดงานชิ้นนั้นเลย" ไม่ใช่ "ปรับปรุงระบบนำทาง"
- ไม่มีอิโมจิท้ายประโยค ไม่มีตัวเลขเปอร์เซ็นต์ลอย ๆ ที่ไม่ได้วัด
- **ตัวตรวจเช็คได้ว่าคำพูดมีจริง แต่เช็คไม่ได้ว่าประโยคไทยที่เขียนใหม่ "แปลว่าอย่างเดียวกัน"**
  — ด่านนั้นคือเจ้าของในขั้นที่ 5 · ร่างทุกชิ้นจึงต้องเขียนให้เทียบกับคำพูดที่ยกมาได้ง่าย

## ประกาศสำคัญที่ทีมเขียนเอง (`kind: "notice"`)

ข่าวที่ไม่ได้มาจากรุ่นแอป — ปิดปรับปรุงระบบ · เปลี่ยนนโยบายข้อมูล · กิจกรรม · เรื่องที่ทุกคนต้องรู้
(เจ้าของสั่ง 15 ต.ค. 69: "ข้อมูลสำคัญเหมือนแอปทั่วไป … ขาดรายงานผ่านพวกเรา")

- **ปักไว้บนสุด** ของจอข่าวสาร ไม่ว่าอ่านแล้วหรือยัง:
  มี `until` = ปักจนถึงเวลานั้น **แล้วหายไปเลย** (ปิดปรับปรุงที่จบแล้วไม่ใช่ข่าว) ·
  ไม่มี `until` = ปัก 7 วัน แล้วลงไปเรียงตามวันที่เหมือนข่าวอื่น
- ไม่ต้องมี `release` · บรรทัดล่างการ์ดเขียนว่า "จาก<by>" (ไม่ใส่ `by` = "ทีม StudentOS")
- พูดถึงเวลาข้างหน้าได้ ("คืนวันเสาร์ 22:00") แต่ **ห้ามแง้มฟีเจอร์** — "เร็ว ๆ นี้" "กำลังจะมา" "เตรียมพบ" ยังไม่ผ่าน
- หลักฐานคือ **คำพูดของเจ้าของ** ที่สั่งให้ประกาศ: `{ "source": "owner", "said": "YYYY-MM-DD", "quote": "…" }`
  - **AI ห้ามเขียนประกาศสำคัญเองจากการเดา** — เขียนได้เฉพาะเมื่อเจ้าของพิมพ์สั่งมา และต้องยกคำพูดนั้นมา
  - เครื่องพิสูจน์ไม่ได้ว่าเจ้าของพูดจริง ตัวตรวจจึง **เตือนทุกครั้ง** ให้เจ้าของอ่านเอง ก่อนย้ายไปไฟล์จริง
  - ข่าวจากรุ่นแอป (`feature` · `theme` · `update` · `fix`) ใช้ `"owner"` ไม่ได้ — ต้องอ้างแพตช์โน้ตหรือคอมมิตเสมอ

```json
{
  "id": "maint-2026-10-18",
  "date": "2026-10-15",
  "until": "2026-10-18T23:00:00+07:00",
  "kind": "notice",
  "title": "ปิดปรับปรุงระบบคืนวันเสาร์",
  "body": "คืนวันเสาร์ 18 ต.ค. 22:00–23:00 น. ระหว่างนี้ซิงก์งานขึ้น cloud ไม่ได้ งานในเครื่องยังใช้ได้ปกติ",
  "evidence": [{ "for": ["title", "body"], "source": "owner", "said": "2026-10-15", "quote": "<คำที่เจ้าของพิมพ์สั่ง>" }]
}
```
(ตัวอย่างรูปแบบเท่านั้น — ไม่ใช่ประกาศจริง)

## รูปแบบหนึ่งประกาศ

```json
{
  "id": "1c57-room-lamp-switch",
  "date": "2026-10-15",
  "release": "1C57",
  "kind": "feature",
  "title": "ห้องของฉัน: กดเปิดปิดไฟเองได้",
  "body": "ป้ายไฟในห้องของฉันกลายเป็นสวิตช์ ...",
  "points": ["...", "..."],
  "action": { "label": "ไปห้องของฉัน", "screen": "scr-room" },
  "evidence": [
    { "for": ["title", "body"], "source": "patchnotes", "quote": "ป้ายไฟในห้อง = สวิตช์ไฟ" },
    { "for": "points.0", "source": "commit:674ed15", "quote": "..." }
  ]
}
```

| ช่อง | กติกา |
|---|---|
| `id` | a-z 0-9 - · ห้ามซ้ำ · ห้ามเปลี่ยนหลังเผยแพร่ (แอปจำว่าอ่านแล้วด้วย id) |
| `date` | YYYY-MM-DD วันที่ของนั้นขึ้นเว็บ · ห้ามอยู่ในอนาคต |
| `release` | เลขรุ่นที่มีหัว `# StudentOS Update <เลข>` ใน PATCHNOTES.md · ไม่บังคับสำหรับ `notice` |
| `kind` | `feature` ฟีเจอร์ใหม่ · `theme` ธีมใหม่ · `update` อัปเดตแอป · `fix` แก้ไข · `notice` ประกาศสำคัญ |
| `until` | ไม่บังคับ · วันเวลาที่ประกาศหมดอายุ (ใส่เขตเวลา `+07:00`) · พ้นแล้วแอปไม่แสดง |
| `by` | ไม่บังคับ · ใครเขียน (ไม่เกิน 30 ตัวอักษร) · ใช้กับ `notice` |
| `title` | 4–60 ตัวอักษร |
| `body` | ไม่เกิน 280 ตัวอักษร |
| `points` | ไม่บังคับ · ไม่เกิน 5 ข้อ ข้อละไม่เกิน 120 |
| `action` | ไม่บังคับ · `screen` ต้องอยู่ใน `NEWS_OPEN` ของ `news.js` (จอที่ `go()` วาดเองได้) |

ประกาศที่ใหม่กว่า 30 วันและยังไม่เปิดดู นับเป็นเลขบนแถว "ข่าวสารจากทีม" ในแท็บฉัน
