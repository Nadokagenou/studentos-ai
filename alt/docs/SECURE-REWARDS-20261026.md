# ระบบรางวัลบัญชีและฉากฉลอง · 26 ตุลาคม 2569

สถานะ: เปิดใช้จริงและส่งขึ้นเว็บแล้ว GitHub Pages ของ 2bcb9f7 สำเร็จ ตรวจห้องชมฉากจากเว็บจริงแล้ว

## สิ่งที่เปลี่ยน

- รางวัล Halloween อ่านใบรับที่ตรงกับบัญชี ฤดูกาล และรหัสของ ไม่อาศัยการเลือกธีมหรือธงในเครื่อง ห้องลองแยกออกจากบัญชีจริง
- โทเคน เช็คอิน สุ่ม ซื้อ คราฟ โค้ด และเครดิตตราปกติใช้บริการ `studentos-economy` เจ้าของบัญชี เวลา ราคา ผลสุ่ม และสิทธิ์ทีมงานตรวจจากเซิร์ฟเวอร์ คำตอบหายใช้รหัสรายการเดิม ไม่แจกซ้ำ การซื้อพร้อมกันใช้ revision และการตรวจยอดทีมงานซ้ำก่อนบันทึก
- ร้านแสดงของอีเวนต์ว่าเป็นรางวัล ไม่แสดงเป็นของซื้อราคา 0 และปุ่มในห้องอธิบายวิธีรับก่อนเลือกของที่ยังไม่มี
- บริการเลือกตราอ่านคลังส่วนตัวหรือข้อมูลเดิมที่ตรึงไว้ แทนข้อมูลสถานะงานที่ผู้ใช้แก้ได้
- งานใหม่รับเครดิตตราและอันดับเมื่อโฟกัสออนไลน์ครบ 5 นาทีแล้วบันทึกว่าเสร็จ งานยังเพิ่ม แก้ และทำเสร็จออฟไลน์ได้ตามเดิม การโฟกัสเควสและพันธสัญญามีคำถามแสงเทียนเป็นช่วง ๆ และหยุดเครดิตขณะรอคำตอบ
- ธีมเรือนลับแลตรวจคำเชิญ 3 คนจาก RPC เดิม และงานที่ยืนยันแล้ว สิทธิ์สามบัญชีที่เจ้าของเคยแจกให้ยังอยู่โดยตรวจ UID จริงที่บริการ ไม่ขยายสิทธิ์ทีมงาน
- ไม่เปลี่ยนเลข 1C60 ไม่เปลี่ยนคีย์เซฟ ไม่รีเซ็ตงานหรือบัญชี ยอดและสิทธิ์ที่มีอยู่บน cloud เก็บเป็น baseline ส่วนสำรองโทเคนเดิมบนเครื่องเก็บแยกรายบัญชีก่อนเขียนยอดยืนยัน

## ฉากและงานของทีม

- รวมงานจาก `origin/main` ถึง d55ce4f: คงภาพจันทร์หยก สีเขียวป่า เพลงระนาด/วง/ปี่รอบ 1:30 และโลโก้หน้าเว็บหลัก ไม่คืนไปใช้ธีมเก่า
- The Cursed Ship ใช้ฉากเดียว 6 วินาทีตามงานล่าสุดของทีม รางวัลอีก 8 ID ใช้จังหวะเดียวกัน มีฉากประจำท่าเรือ ไร่ฟักทอง ปราสาท และสุสาน แยกภาพ จุดรับใบงาน บทบรรยาย ตรา และแสง ไม่ต้องเล่นเกม แต่ละรางวัลมีพลังจบงานของตนเอง: ผีน้ำ เผาฟักทอง ค้างคาว ดอกไม้งอก ฟันแตก เงาคราส กรง/ประตู และคลื่นเรือ
- Epic/Legendary ของไบโอมเดียวกันใช้ภาพร่วมกัน แต่คงชื่อ ตรา และสิทธิ์เดิม ไม่มีการลบรางวัล
- ห้องชมฉาก `alt/halloween/rewards/cinematic-preview.html` ดูได้โดยไม่เข้าสู่ระบบ การกดเล่นยินยอมให้เคลื่อนไหวในหน้านั้นเท่านั้น ไม่เปลี่ยนการตั้งค่าของแอปหรือระบบ ไม่เขียนรางวัล
- ภาพไบโอมใหม่สร้างด้วย built-in image_gen รายละเอียดบรีฟอยู่ใน `../halloween/docs/cinematic-scenes-20261026/prompts.json` ไฟล์ใช้งานอยู่ใน `../halloween/season/biome-cinematics/` มีภาพฉากสามภาพและวิญญาณโปร่งใสหนึ่งภาพ WebP รวมประมาณ 1.46 MB ใช้ alpha จากเครื่องมือโดยตรง ไม่ลบพื้นหลังด้วยสคริปต์ เก็บต้นฉบับที่เครื่องมือคืนไว้
- ภาพเรือนไทยริมคลองเป็นแนวสำรวจ เก็บใน `../halloween/docs/thai-ghost/explorations/` ไม่แทนภาพจันทร์หยกที่ทีมเลือกแล้ว แนวคิดอ้างอิงตำนานหลายสำนวน ไม่อ้างว่าเป็นประวัติศาสตร์พิสูจน์ได้: [สารานุกรมวัฒนธรรมไทย ศูนย์มานุษยวิทยาสิรินธร](https://db.sac.or.th/thailand-cultural-encyclopedia/detail.php?id=3467), [หอภาพยนตร์](https://www.fapot.or.th/main/heritage/view/36)

## ลำดับเผยแพร่

1. ตรวจ migration เตรียมระบบโดยยัง `active=false` และตรวจสิทธิ์ซ้ำ
2. เผยแพร่บริการใหม่และ bundle ที่ทดสอบแล้ว โดยเปิด JWT verification ทุกตัว
3. ก่อนส่ง client ใหม่ ตรึงยอด cloud และเปลี่ยนกระดานในธุรกรรมเดียว เปิด guard พร้อม baseline เพื่อไม่ให้ client ช่วงเปลี่ยนผ่านเขียนทับสิทธิ์เดิม
4. ส่ง root เฉพาะตัวเชื่อมคลังบัญชี และ ALT พร้อมฉาก/ห้องชม คง cache แยกกัน ตรวจเว็บจริงและสิทธิ์หลังส่ง

## ผลเผยแพร่จริง

การตรวจอนุมัติกลับมาใช้งานได้แล้ว จึงส่งผ่านเครื่องมือเดิมตามลำดับ: prepare migration `20261026140834` สำเร็จ (active=false), บริการ `studentos-economy` v1 / `halloween-event` v5 / `halloween-badge` v3 ACTIVE และเปิด JWT verification ทุกตัว ตรวจ HTTP ผู้ไม่เข้าสู่ระบบ 401 และ allowed-origin OPTIONS 204 ครบทั้งสามตัว activation migration `20261026142938` สำเร็จ (active=true) เก็บ baseline ครบ23/23บัญชี RLSครบ7ตาราง ไม่มี browser grants ไม่มีบัญชีจำลองค้าง และ counters ของยอดทีมงานกระทบครบ ส่ง client ที่ 2bcb9f7 แล้ว

เพิ่มการกระทบยอด staff grants/debits ที่ยังไม่ถูกรับเข้าคลังลง baseline โดยไม่แก้ user_state เดิม ทดสอบบัญชีจำลองยอด50 +25 -5 ได้70 ไม่ซ้ำ รักษาอันดับเก่าและปฏิเสธงานปลอม ผ่านบนฐานข้อมูลจริงแบบ rollback ไม่มีบัญชีจำลองค้าง
