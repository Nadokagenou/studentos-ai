ผังคอม ALT ถูกปล่อยก่อนใน `eb94cd9` และรวมเข้ามาแล้ว ส่วน StudentOS Fresh Start เป็นคนละงาน ไม่ได้นำมาปล่อย
คำสั่งของเจ้าของครั้งนี้อนุญาตให้แก้ root ตามข้อยกเว้นใน AGENTS.md ที่ห้ามแตะ root ถ้าไม่ได้สั่ง

## เพิ่มหลังเจ้าของลองเล่น · เมนูข้างและอันดับ

- เพิ่มทางลัด แผนวันนี้ ปฏิทิน อันดับ กล่องเข้า และตั้งค่า โดยเรียกหน้าจอเดิมผ่าน `go`, `goTlMode`, `openBoard` ไม่สร้างระบบซ้ำ
- ปุ่มอันดับเดิมบนหัวจอไม่ได้ถูกลบ แอปเดิมแสดงเมื่อเข้าบัญชีและเปิดฟีเจอร์social พรีวิวเป็นguestจึงไม่มีปุ่มนั้น ทางลัดใหม่เปิดกระดานguestเดิมได้ และไม่สร้างคะแนน/สิทธิ์ปลอม
- เพิ่มปุ่มซ่อน/เปิดเมนู จำสถานะในคีย์ใหม่ `studentos.desktop.sidebar` ไม่แก้คีย์เดิมหรือข้อมูลที่ซิงก์ของแอป
- เปิดผังใหม่เฉพาะจอ≥1024pxที่มีhoverและpointer:fine ทั้งCSS/ตัวโหลด/ตัวควบคุมใช้เงื่อนไขเดียวกัน จอสัมผัสล้วนแม้กว้างก็ไม่ผ่านเงื่อนไข
- `desktop-entry.js` ไม่โหลดโมดูลเมนูบนมือถือเมื่อเปิดครั้งแรก หากย่อมาจากคอมจะถอดปุ่มใหม่ คืนinert/idของเมนูเดิม และลบสถานะผังคอมออก
- เทียบด้วยข้อมูลจำลองguest: ตัวควบคุมเดิม366จุดและจอเดิม46จอยังอยู่ ไม่มีรายการหาย เทียบ375×812และ768×1024แล้วเรขาคณิตของกรอบ/เมนู/ปุ่มเริ่ม/ความสูงเนื้อหาตรงbaseline
- ตรวจ375ที่เปิดใหม่: ไม่โหลดdesktop.js และไม่มีปุ่มคอม ตรวจซ่อนเมนูบน1024แล้วย่อ375: เมนูเดิมกลับมาและไม่ค้างinert ตรวจกลับ1440แล้วเปิดเมนูได้
- ตรวจหน้าล็อกอินเดิมโดยเปิดrouteในเครื่อง: ปุ่มคอมถูกถอดออก และขนาดตรงbaseline ไม่ได้ทดสอบเข้าสู่บัญชีจริง
- `devtools/desktop-parity-review.html` เป็นตัวเทียบก่อน/หลังในiframe แสดงปุ่ม/จอที่หายและผลเทียบขนาด ไม่ถูกโหลดในแอปจริง

## การปรับ

- เพิ่ม `desktop.css` ผังจอกว้างตั้งแต่1024pxพร้อมเมาส์/การชี้ ใช้กรอบแอป100%×100dvh ไม่มีกรอบมือถือและนาฬิกาจำลอง
- ใช้ปุ่มนำทางเดิมทั้ง5ปุ่มในแถบซ้ายกว้าง248px (224px ที่1024–1199px) พร้อมทางลัด5ปุ่ม ป้ายและแบดจ์เดิมยังอยู่
- หน้าวันนี้: งานที่ระบบเลือกด้านซ้าย น้องฮูกและคิวที่เหลือด้านขวา ช่องถามและทางลัดเดิม8ปุ่มเป็นแถวกะทัดรัด
- หน้าอื่นขยายพื้นที่เนื้อหาและฟอร์ม แผ่นเพิ่มงานกว้าง600px โฟกัสคลุมจอ กล่องแจ้งผลยังเป็นแคปซูลสูงตามข้อความ
- สีอ่านจากโทเคนธีมเดิม ไม่มีการบังคับเปลี่ยนธีมหรือเพิ่มไลบรารีกราฟิก ตัวควบคุมใหม่มีเฉพาะการแสดงเมนูและเรียกทางเดินเดิม
- `index.html` เพิ่มlink CSSกับตัวโหลดเมนูเฉพาะคอม `sw.js` แคชไฟล์ใหม่และเปลี่ยนท้ายชื่อแคช ไม่เปลี่ยนเลขรุ่น1C60หรือนโยบายpush
- ไม่แก้ `style.css`, `app.js`, engine/planner, config หรือคีย์ข้อมูล งานหลักอยู่ที่root; รอบตรวจละเอียดแก้ปุ่มกลับและแถบบันทึกแบบเดียวกันใน `alt/desktop.css` ด้วย

## ตรวจแล้ว

ข้อมูลจำลองในเครื่อง วันที่20ตุลาคม2569 ตั้งแต่19:00 และ22:30 มีป้ายระบุในภาพ ไม่มีบัญชี cloud และใช้SWจำลองเฉพาะพรีวิว

- จอ1280×720: แอป1280×720 เมนู248px เนื้อหา1032px ปุ่มเริ่มและทางลัด8ปุ่มอยู่ในจอในกรณีตัวอย่างปกติ
- จอ1024×768: แอปเต็มจอ เมนู224px หน้าวันนี้scrollHeightเท่ากับclientHeight768 ปุ่มเริ่มและทางลัดอยู่ในจอ ไม่มีแนวนอนล้น
- จอ1440×900: แอปเต็มจอ หน้าวันนี้scrollHeightเท่ากับclientHeight900 ไม่มีแนวนอนล้น
- ย่อ1440→960: ผังเดิมกลับมา ไม่มีแนวนอนล้น
- มือถือ375×812: ถอดdesktop.cssเพื่อเปรียบเทียบแล้วตำแหน่งปุ่ม/ขนาดเนื้อหาเท่ากัน (home1032px, screen803/scroll1108px) ยืนยันว่าไม่เกิดความยาวเพิ่มจากงานนี้
- หน้าแรกมือถือเดิมเลื่อนได้อยู่แล้วในข้อมูลตัวอย่างนี้ ไม่อ้างว่ากฎ375×812ไม่เลื่อนผ่านหรือทดสอบFPSเครื่องจริงแล้ว
- เปิดหน้า งานวันนี้/รายการ, แผนวันนี้, ตารางเต็มวัน, ผู้ช่วย, โปรไฟล์, ตั้งค่า และฟอร์มเพิ่มงานได้
- บันทึกงานตัวอย่างได้ เริ่มโฟกัสและทำเสร็จได้ จอสรุปบอกชีววิทยาเป็นงานถัดไป กลับหน้าแรกแล้วจำนวนงานลดถูกต้อง
- แผ่นเพิ่มงานอยู่กลางจอ โฟกัสเต็ม1280×720 ปุ่มปิด/เสร็จไม่ถูกเมนูบัง
- กล่องแจ้งบันทึกมีขนาด480×64 อยู่y16 ไม่ยืดลงทั้งจอ
- ตรวจภาพธีมlight/dark/galaxy/magic และสถานะงานว่าง/หมดเวลาว่าง ไม่มีการ์ดซ้อนทับกัน
- การเข้าสู่บัญชีจริง, cloud AI, การส่งข้อความ, การแจ้งเตือนจากระบบ และโหมดออฟไลน์ในเบราว์เซอร์จริงไม่ได้ทดสอบในรอบนี้
