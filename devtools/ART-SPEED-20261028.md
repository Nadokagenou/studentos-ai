# รูปโหลดช้าและจูนมินิเกม · ชุดปิดงาน 28 ตุลาคม 2569

พบสาเหตุจากโค้ดและไฟล์จริง: ฉาก/ภาพแนวตั้ง/sprite ใช้ WebP ขนาดใหญ่ ไฟล์หลักประมาณ 1.5–3 MB และ main service worker บังคับ network-first พร้อม no-store กับรูปด้วย ทำให้กลับฉากยังรอเครือข่าย ส่วน controller มินิเกมคัดลอกเซฟทั้งก้อนด้วย JSON ทุกการกด และวาดสถานะซ้ำตอนจบรอบ

- เข้ารหัสภาพเดิมใหม่ 15 ไฟล์เป็นชื่อ -fast-v1.webp จากรวม32,256,800 เหลือ5,857,896 bytes ลด81.84% นี่คือผลรวมชุดที่ปรับ ไม่ใช่ payload ที่ทุกหน้าโหลดครั้งเดียว คงมิติภาพทุกไฟล์และตรวจ alpha ของ sprite ตรงเดิมทุกพิกเซล จึงใช้ตำแหน่งจุดกด/ช่อง sprite เดิม ภาพต้นฉบับยังอยู่
- เปลี่ยนเส้นทางฉากทั้ง4ไบโอม/โถง/ห้อง/ตัวละคร/อาวุธ/พื้นหลังเกมเป็นชุดเบา เพิ่ม cache-first เฉพาะรูปที่ชื่อมีเวอร์ชันใน event/assets ใช้ cache รูปร่วมข้ามรุ่น main และรวมคำขอพร้อมกันของรูปเดียวกัน โค้ดแอปยังตรวจอัปเดตแบบ network-first ตามเดิม และ main worker ไม่ดัก ALT
- controller คัดลอกเฉพาะ game และ container ที่ game-move/brain-move เขียน ไม่ serialize ประวัติทั้งเซฟ รักษา verified save เดิมไม่เปลี่ยนจนเซิร์ฟเวอร์ตอบ ลดการแจ้งวาดสถานะซ้ำตอน flush/ack

หลักฐาน: fixture5000รายการledger (เซฟ349,739bytes), 6การกดเรือ, 50รอบบนเครื่องนี้ medianงานคำนวณlocal22.1101→0.1376ms และp9524.1831→0.6261ms เป็น benchmarkของcontroller ไม่รวมDOM/เน็ต และไม่ใช่การรับรองมือถือจริง ชุดรวม394เคสผ่าน/mainSW6ผ่าน รวมcacheไม่เรียกเครือข่ายซ้ำ, single-flightรูป, ALT isolation, เกม5แบบที่ verified save ทั้งก้อนถูกfreezeแล้วเล่นครบก่อนackได้ และเกมพักสมอง6แบบเดิม

หน้าQAใช้โค้ดmainจริง+เซฟจำลองที่375×812 ตรวจท่าเรือ/สวนJack/คฤหาสน์/สุสาน ไม่พบรูปเสีย/JSerror/overflow/ปุ่มถูกบังในรอบตรวจ ตรวจภาพใหม่โดยคงรูปทรงและขนาดเดิม ไม่ใช่การวัดโหลดผ่านมือถือจริงหรือเครือข่ายมือถือ

ตามคำสั่งผู้ใช้ มอบชดเชย50Candyต่อบัญชีที่มีหลักฐานใช้งานวันที่28ต.ค.เวลาไทย ณรอบส่ง: รวม11บัญชี/550Candy ส่งข้อความขอโทษส่วนตัว11รายการ และผู้ให้บริการPushตอบรับ6บัญชีที่มีsubscription เก็บreceiptแคมเปญที่กันซ้ำและledger50ต่อบัญชีอย่างละ1รายการ ใช้lockเดียวกับบริการเกม+revisionเพื่อไม่ทับเซฟระหว่างเล่น มีสำรองก่อนทำไว้เฉพาะoutputsที่ไม่เผยแพร่ ไม่ใช้โทเคนแทนCandy และไม่บังคับเปิดสิทธิ์แจ้งเตือน

ผู้ใช้ขอจบงานวันนี้หลังชุดนี้ จึงไม่ขยายงานอื่นต่อ การเปิดรอบและยืนยันผลยังต้องใช้เครือข่าย การตรวจตามกำหนดครั้งถัดไปไม่ควรเริ่มงานใหม่ในวันที่28ต.ค.
