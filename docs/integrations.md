# ตัวเชื่อมกับแพลตฟอร์มอื่น (Integrations)

เป้าหมาย: **งานที่ครูสั่งผ่านแพลตฟอร์มอื่น เข้ามาอยู่ในรายการงานของ StudentOS เอง**
ผ่าน API ทางการของแต่ละเจ้าเท่านั้น — ไม่มีการ scrape ไม่มีการอ่านแชทของใคร
และไม่มีการขอรหัสผ่านของระบบอื่นจากผู้ใช้เลยสักที่

---

## เส้นทางของงานหนึ่งชิ้น

```
ต้นทาง (Classroom API / ปฏิทิน ICS)
  → Adapter            _shared/classroom.ts · _shared/ics.ts   แปลงเป็น StandardTask
  → integration_items  ทะเบียน "เคยเห็นงานนี้แล้ว"             ← ที่จับซ้ำอยู่ตรงนี้
  → inbox_items        ท่อเดิมที่บอท LINE ใช้อยู่แล้ว
  → pullInbox()        ฝั่งแอป (linelink.js)
  → inboxAddSynced()   ข้ามตัวแกะข้อความ เพราะข้อมูลมีโครงอยู่แล้ว
  → งานในแผน
```

**ห้ามให้ฝั่งเซิร์ฟเวอร์เขียนงานลง `user_state.data` ตรง ๆ** ข้อมูลผู้ใช้ทั้งคนเป็น JSON
ก้อนเดียวที่แอปเป็นคน push ทับทั้งก้อนทุกครั้งที่มีอะไรเปลี่ยน — เขียนแทรกจากฝั่งเซิร์ฟเวอร์
เมื่อไหร่ งานที่เพิ่งใส่จะหายเงียบ ๆ ภายใน 1.5 วินาที โดยไม่มี error ให้ใครเห็น

## Standard Task Model

รูปแบบกลางที่ทุก adapter ต้องแปลงของจากต้นทางมาเป็น (`_shared/integrations.ts`)

| ช่อง | ความหมาย |
|---|---|
| `sourceId` | id จากต้นทาง ที่นิ่งเมื่อเนื้อหาถูกแก้ |
| `title` | ชื่องาน |
| `detail` | รายละเอียดจากต้นทาง (ตัดที่ 400 ตัวอักษร) |
| `subject` | ชื่อคอร์สตามที่ต้นทางเรียก |
| `due` | ISO 8601 · `null` = ต้นทางไม่ได้กำหนด |
| `url` | ลิงก์กลับไปที่งานต้นทาง |
| `type` | `homework` · `exam` · `event` |
| `cancelled` | ต้นทางลบ/ยกเลิกแล้ว |

**ไม่มีช่อง priority โดยตั้งใจ** — ไม่มี API เจ้าไหนรู้ว่างานไหนสำคัญกว่ากันสำหรับเด็กคนนี้
ความสำคัญเป็นสิ่งที่ `engine.js` คิดเองจากกำหนดส่ง/คะแนน/นิสัยของเจ้าของเครื่อง

ฝั่งแอปแปลงต่ออีกชั้นหนึ่ง (`inbox.js · syncParsed`) เพราะ StudentOS ใช้รายชื่อวิชาตายตัว
ชื่อคอร์สอิสระจึงถูกจับคู่ด้วย `parseAssignment()` ตัวเดิมของแอป แล้วเก็บชื่อเดิมไว้ที่ `srcSubject`

### การจับซ้ำ

| ชั้น | กุญแจ | ใช้ตอนไหน |
|---|---|---|
| เซิร์ฟเวอร์ | `integration_id + source_id` | ไม่ส่งงานเดิมซ้ำทุกรอบ sync |
| แอป | `srcKey = provider + ':' + source_id` | จับว่าเป็นงานใบเดิมที่รับไปแล้ว |
| แอป (ข้ามต้นทาง) | ข้อความ (`sameAssignment`) | ครูสั่งงานเดียวกันทั้งใน LINE และ Classroom — ใบที่มาทีหลัง **ผูก srcKey เข้ากับใบเดิม** ไม่สร้างใบที่สอง |

### เมื่อต้นทางแก้หรือลบ

* **แก้** — เทียบ `fingerprint` ที่คิดจาก "สิ่งที่นักเรียนจะเห็น" ไม่ใช่จาก `updateTime`
  (Classroom ขยับ `updateTime` ทุกครั้งที่ครูแตะอะไรก็ตาม รวมถึงเรื่องที่ไม่เกี่ยวกับนักเรียน)
  เปลี่ยนจริงเท่านั้นถึงส่งอัปเดต · ฝั่งแอปแก้ **ชื่อ/กำหนดส่ง/วิชา** ของใบเดิม
  แต่ไม่แตะ **ติ๊กเสร็จ · ความคืบหน้า · เวลาที่ประเมินเอง · งานย่อย** ซึ่งเป็นของนักเรียน
* **เก่าเกิน 24 ชม.** — จดไว้ในทะเบียนว่ารู้จักแล้ว แต่ **ไม่ส่งเข้ากล่องเข้า**
  เจอตอนทดสอบกับฟีดจริง: ปฏิทินหนึ่งใบมี 317 รายการย้อนไปถึงปี 2021 ถ้าส่งทั้งหมด
  กล่องเข้าที่มีเพดาน 150 จะถูกงานที่ส่งไปแล้วเมื่อปีที่แล้วกลืนจนงานพรุ่งนี้หายไปท้ายแถว
  (เผื่อไว้หนึ่งวันเต็ม เพราะงานที่ครบกำหนดเมื่อเช้ายังส่งตามได้ · ครูเลื่อนกำหนดมาข้างหน้า
  เมื่อไหร่ ลายนิ้วมือเปลี่ยน แล้วมันกลับเข้าเส้นทางเองโดยอัตโนมัติ)
* **ลบ/ยกเลิก** — ย้ายไปถังขยะ (กู้คืนได้) ไม่ลบถาวรแทนคน
  และ **บอกเฉพาะงานที่ยังไม่ถึงกำหนด** เท่านั้น เพราะปฏิทินที่ตัดงานเก่าออกหลัง 30 วัน
  จะทำให้งานที่ส่งไปแล้วเมื่อเดือนที่แล้วหายพร้อมกันสิบใบ ซึ่งไม่ใช่การยกเลิก

## แต่ละเจ้าทำอะไรได้บ้าง

### ปฏิทินของโรงเรียน (ICS) — ใช้ได้ทันที

| | |
|---|---|
| **สิทธิ์ที่ขอ** | ไม่มี — ผู้ใช้วางลิงก์ปฏิทินที่ระบบของโรงเรียนออกให้เอง |
| **ซิงก์อะไร** | ชื่องาน · กำหนดส่ง · ลิงก์กลับ · การยกเลิก |
| **ใช้กับอะไรได้** | Canvas (Calendar Feed) · Moodle (Export calendar → Get calendar URL) · พอร์ทัลโรงเรียนและปฏิทินอื่นที่ออกลิงก์ `.ics` |
| **ข้อจำกัด** | ปฏิทินไม่มีคะแนน ไม่มีสถานะ "ส่งแล้ว/ยังไม่ส่ง" · เหตุการณ์ที่เกิดซ้ำ (RRULE) ถูกข้ามทั้งหมดโดยตั้งใจ (เกือบทั้งหมดคือคาบเรียน ไม่ใช่การบ้าน) |
| **ความลับ** | ลิงก์นี้คือความลับ ใครถือก็อ่านปฏิทินของเจ้าตัวได้ จึงถูกเข้ารหัสเก็บเหมือน token และไม่เคยถูกส่งกลับมาให้เบราว์เซอร์อีก |

### Google Classroom — โค้ดพร้อม รอกุญแจฝั่งเซิร์ฟเวอร์

| | |
|---|---|
| **สิทธิ์ที่ขอ** | `classroom.courses.readonly` · `classroom.coursework.me.readonly` · `classroom.student-submissions.me.readonly` · `userinfo.email` |
| **ซิงก์อะไร** | งานที่ครูมอบหมาย · คำสั่ง · กำหนดส่ง · ชื่อคอร์ส · ลิงก์กลับ · **ข้ามงานที่ส่งไปแล้ว** (TURNED_IN / RETURNED) |
| **ไม่ทำอะไร** | ไม่อ่านคะแนน · ไม่อ่านรายชื่อหรือข้อมูลของเพื่อนร่วมห้อง · ไม่เขียนอะไรกลับไปที่ Classroom เลย |
| **ข้อจำกัด** | scope ชุดนี้เป็น **restricted** ของ Google → โหมด Testing ใช้ได้ทันทีแต่จำกัด **100 บัญชี** · เกินกว่านั้นต้องผ่าน **CASA security assessment** และต่ออายุทุกปี |
| **ข้อจำกัดข้อสอง** | แอดมิน Google Workspace ของโรงเรียนปิดกั้นแอปนอกทั้งโดเมนได้ — ปิดเมื่อไหร่ นักเรียนในโดเมนนั้นเชื่อมไม่ได้เลย และนั่นเป็นสิทธิ์ของโรงเรียนจริง ๆ ไม่ใช่บั๊ก |
| **ไม่มี** | Classroom ไม่มีช่อง "นี่คือข้อสอบ" และ `maxPoints` คือ *เต็มกี่คะแนน* ไม่ใช่ *กี่เปอร์เซ็นต์ของเกรด* จึงไม่ถูกแปลงเป็น `scorePct` |

### Google Calendar — โค้ดพร้อม ใช้กุญแจดอกเดียวกัน

| | |
|---|---|
| **สิทธิ์ที่ขอ** | `calendar.events.readonly` · `userinfo.email` |
| **ซิงก์อะไร** | วันสอบ/กิจกรรมที่โรงเรียนลงปฏิทินไว้ |
| **ข้อได้เปรียบ** | scope นี้เป็นแค่ **sensitive** ไม่ใช่ restricted → ไม่ต้องผ่าน CASA |

### Microsoft Teams — ทำไม่ได้ในทางปฏิบัติ

Microsoft เปิด API จริง (Graph · `EduAssignments.ReadBasic`) แต่สิทธิ์ชุดนั้น
**ต้องให้ผู้ดูแลระบบของโรงเรียนอนุมัติแอปทั้ง tenant ก่อน** นักเรียนกดยอมรับเองไม่ได้เลยสักคน
และใช้ได้เฉพาะบัญชีโรงเรียน ไม่รองรับบัญชี Microsoft ส่วนตัว

จึงยังไม่ทำ และขึ้นในแอปว่า **"รอโรงเรียนอนุมัติ"** ซึ่งเป็นสถานะที่สามที่ต่างจาก
"รอตั้งค่า" (รอเรา) และ "ต่อไม่ได้" (ไม่มีวันได้) — จะเปิดได้ก็ต่อเมื่อมีโรงเรียนที่พร้อมอนุมัติ

### LINE — ไม่มี API ให้อ่านแชท และจะไม่มี

**ไม่มี API ทางการของ LINE ที่ให้แอปภายนอกอ่านข้อความ**
ไม่ว่าจะเป็นแชทส่วนตัว · แชทกลุ่ม · กลุ่มห้องเรียน หรือข้อความที่ครูส่ง

* **LINE Login** ให้ได้แค่โปรไฟล์ (ชื่อ · รูป · user id) ไม่มีสิทธิ์อ่านข้อความใด ๆ
* **Messaging API** บอทเห็นเฉพาะข้อความในห้องที่บอทถูกเชิญเข้าไปเท่านั้น
  และเห็นตั้งแต่ตอนที่ถูกเชิญเป็นต้นไป ย้อนหลังไม่ได้

สิ่งที่ StudentOS ทำจึงเป็นทางเดียวที่มีอยู่จริง: **บอทในกลุ่มห้องเรียน** (`line-webhook`)
ครูสั่งงานในกลุ่มครั้งเดียว เข้าระบบให้ทุกคนในห้องที่เชื่อมไว้พร้อมกัน

**ไม่มีแผนจะหาทางอ้อม** — การอ่านแชทส่วนตัวของนักเรียนไม่ใช่ของที่ควรทำแม้จะทำได้

## ตั้งค่าฝั่งเซิร์ฟเวอร์

### 1. กุญแจเข้ารหัส (จำเป็นเสมอ แม้ใช้แค่ ICS)

```bash
openssl rand -base64 32
```

Supabase → Edge Functions → Secrets → `INTEGRATION_KEY` = ค่าที่ได้

> กุญแจนี้หาย = การเชื่อมทุกเส้นของทุกคนถอดรหัสไม่ออกอีกเลย ทางแก้คือให้ผู้ใช้กดเชื่อมใหม่
> **ห้ามเปลี่ยนโดยไม่ได้ตั้งใจให้ทุกคนต้องเชื่อมใหม่พร้อมกัน**

### 2. กุญแจ Google (เฉพาะเมื่อจะเปิด Classroom / Calendar)

1. https://console.cloud.google.com → โปรเจกต์เดิมที่ใช้ทำ Google Login ก็ได้
2. **APIs & Services → Library** → เปิด **Google Classroom API** และ **Google Calendar API**
3. **OAuth consent screen** → External → เพิ่ม scope ทั้งสี่ตัวข้างบน → เพิ่มตัวเองเป็น Test user
4. **Credentials → OAuth client ID → Web application** → ใส่ Authorized redirect URI:

```
https://yunbytxtgghizrdqftvj.supabase.co/functions/v1/oauth-callback
```

5. ตั้ง secret สองตัว: `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET`

ยังไม่ตั้ง = ปุ่ม "เชื่อมด้วย Google" ไม่โผล่ (ขึ้นเหตุผลแทน) — ปุ่มที่กดแล้ว error แย่กว่าปุ่มที่ยังไม่มี

### 3. Deploy แล้วตั้งนาฬิกา

```bash
supabase db push
supabase functions deploy integrations
supabase functions deploy sync-integrations
supabase functions deploy oauth-callback
```

> `oauth-callback` ต้อง **ปิด Verify JWT** (ตั้งไว้ใน `config.toml` แล้ว) เพราะ Google
> เป็นคนพาเบราว์เซอร์ของผู้ใช้มาที่ URL นั้น มันไม่มีทางแนบ JWT ของเรามาด้วย
> ด่านจริงคือ `state` ที่เซ็นด้วย `INTEGRATION_KEY` อายุ 10 นาที และระบุตัวผู้ใช้

cron ถูกตั้งจาก migration `20260917090100` (ทุก 30 นาที) — ต้อง deploy ฟังก์ชันก่อนรัน
ไม่งั้น cron จะยิงไปที่ 404 ทุกครึ่งชั่วโมงโดยรายงานว่า "succeeded"

## ความปลอดภัย

* **กุญแจไม่เคยผ่านเบราว์เซอร์** — refresh token และลิงก์ปฏิทินลับถูกเข้ารหัส AES-GCM
  ด้วยกุญแจที่อยู่ใน Edge Function Secrets ไม่ได้อยู่ในฐานข้อมูล ต้องขโมยสองที่พร้อมกันถึงจะอ่านได้
* **ตาราง `integrations` เปิด RLS แล้วไม่มี policy สักข้อ** = ฝั่งเบราว์เซอร์แตะไม่ได้เลย
  แม้แต่แถวของตัวเอง เพราะ RLS คุมได้แค่ "แถวไหน" ไม่ได้คุม "คอลัมน์ไหน"
* ทางเข้าเดียวคือ Edge Function `integrations` (verify_jwt = true) ซึ่งคืนเฉพาะคอลัมน์ที่โชว์ได้
* **ตัดการเชื่อมแล้วถอนสิทธิ์ที่ต้นทางจริง** (`oauth2.googleapis.com/revoke`) ก่อนลบแถวของเรา
  ลบแถวอย่างเดียวคือ "เราลืม" แต่สิทธิ์ยังค้างอยู่ในบัญชีของผู้ใช้ตลอดไป
* **กัน SSRF** — URL ปฏิทินที่ผู้ใช้พิมพ์เองถูกกรอง host ที่ชี้เข้าเครือข่ายภายในทิ้งก่อนยิง
* ขอ scope น้อยที่สุดที่ฟีเจอร์ต้องใช้ · อ่านอย่างเดียวทุกตัว · ไม่มี secret ตัวไหนอยู่ในรีโปนี้

## AI ถูกใช้ตรงไหนบ้าง

**ไม่ถูกใช้เลยในเส้นทางนี้** — ข้อมูลจาก API มีโครงอยู่แล้ว (`meta.structured` = ข้ามตัวแกะข้อความ)
เอา AI ไปเดาสิ่งที่ API บอกตรง ๆ อยู่แล้วคือการเพิ่มโอกาสผิดให้ข้อมูลที่ถูกอยู่แล้ว แถมเสียเงิน

AI ยังทำงานเหมือนเดิมกับของที่ **ไม่มีโครง**: ข้อความจากกลุ่ม LINE · รูปที่สแกน · เสียงพูด ·
ข้อความที่แชร์เข้ามา และการจัดลำดับ/วางแผนเวลา ซึ่งไม่มี API เจ้าไหนตอบให้ได้

## เวลาเชื่อมแล้วไม่มีงานเข้า ให้ดูตรงนี้

```sql
select provider, account, status, error_msg, last_sync_at, next_sync_at
  from public.integrations;

select source_id, title, due, state, sent_at
  from public.integration_items order by updated_at desc limit 20;
```

* `status = needs_reauth` → ผู้ใช้ต้องกดเชื่อมใหม่ (ระบบไม่ลองเองเพราะลองไปก็ไม่หาย)
* `status = error` → ต้นทางมีปัญหาชั่วคราว ระบบถอยห่างเอง (30 นาที → 2 ชม. → 8 ชม. → วันละครั้ง)
* มีแถวใน `integration_items` แต่งานไม่ขึ้นในแอป → ดูที่ `inbox_items` ว่า `consumed` หรือยัง
  และดูว่าตัวเชื่อมนั้นถูกปิดสวิตช์ไว้ในเครื่องหรือเปล่า
