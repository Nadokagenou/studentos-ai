# เทสต์ของ sync-integrations

รันบน **Node ธรรมดา** ไม่ต้องมี Deno ไม่ต้องมี Supabase ไม่ยิง push จริง ไม่ยิงเน็ตจริง

```bash
cd supabase/functions/sync-integrations/__tests__
npx --yes esbuild@0.23.1 --bundle --format=esm "--external:npm:*" "--external:jsr:*" \
  --outfile=fn.mjs ../index.ts
npx --yes esbuild@0.23.1 --bundle --format=esm --outfile=crypto.mjs ../../_shared/integrations.ts
node -e "const fs=require('fs');const s=fs.readFileSync('fn.mjs','utf8');fs.writeFileSync('fn.mjs',s.replace('\"npm:web-push@3.6.7\"','\"./wp.mjs\"').replace('\"jsr:@supabase/supabase-js@2\"','\"./sb.mjs\"'))"
node run.mjs
```

`fn.mjs` กับ `crypto.mjs` สร้างใหม่ได้ตลอดจึงอยู่ใน `.gitignore` —
**สร้างใหม่ทุกครั้งที่แก้ `index.ts` หรือ `_shared/`** ไม่งั้นเทสต์จะผ่านกับโค้ดรุ่นเก่า

`crypto.mjs` มีไว้เพื่อให้เทสต์ `seal()` ลิงก์ปฏิทินด้วย**ฟังก์ชันตัวเดียวกับที่ของจริงใช้**
ไม่ใช่เขียนรูปแบบ `v1.<iv>.<ct>` ขึ้นมาเองในเทสต์ ซึ่งจะกลายเป็นการทดสอบสำเนาที่เพี้ยนได้

## สิ่งที่เทสต์ชุดนี้คุ้มครอง

ชั้นแจ้งเตือน "มีของใหม่ไหลเข้ามา" ซึ่งทดสอบด้วยมือแทบไม่ได้เลย เพราะทุกเงื่อนไข
ต้องจัดเวลาและสภาพข้อมูลให้เกิด (กลางดึก · ซิงก์รอบแรก · subscription หมดอายุ ·
ปฏิทินที่มีงานทั้งเทอม 80 ใบเข้ามาพร้อมกัน)

และเป็นบั๊กชนิด **เงียบ** เหมือนกับของ send-reminders: คนที่โดนยิง 80 ดอกรวดจะปิด
การแจ้งเตือนทิ้งแล้วไม่มีทางกลับมา ส่วนคนที่ไม่ได้รับเลยก็ไม่มีทางรู้ว่าตัวเองไม่ได้รับ

## ⚠️ นาฬิกาสองเรือน — กับดักที่ทำให้เทสต์ตกทั้งชุดโดยโค้ดไม่ผิดเลย

เทสต์หยุด `Date.now()` ไว้เพื่อคุมชั่วโมงไทย (เทสต์กลางดึก) **แต่ `new Date()` ที่ไม่มี
อาร์กิวเมนต์ไม่ได้เรียก `Date.now()`** มันอ่านนาฬิกาเครื่องตรง ๆ

ตัวฟังก์ชันใช้ `new Date().toISOString()` ตอนกรอง `next_sync_at` — แถวที่เทสต์ตั้งเวลาไว้
ด้วยเวลาที่ถูกหยุดจึงกลายเป็น "อนาคต" เมื่อเทียบกับเวลาจริง แล้วไม่ถูกเลือกมาซิงก์เลยสักแถว
(รอบแรกที่เขียนเทสต์ชุดนี้ตก 15 จาก 23 เพราะเรื่องนี้ล้วน ๆ)

คอลัมน์ที่เกี่ยวกับ "ถึงคิวหรือยัง" ในเทสต์จึงต้องใช้ `REAL()` เสมอ ไม่ใช่ `Date.now()`
และ `freezeThaiHour()` หยุดเวลาไว้ที่ **วันจริงวันนี้** ไม่ใช่วันสมมติ

## ของจำลอง

`stubs.js` ทำ query builder ของ supabase-js **เฉพาะรูปที่ `index.ts` ใช้จริง**
(`insert` · `upsert` พร้อม `onConflict` · `update` · `delete` · `lte` · `not is null` ·
`maybeSingle`) — เพิ่มคิวรีรูปใหม่ในฟังก์ชันเมื่อไหร่ ต้องมาเพิ่มที่นี่ด้วย ไม่งั้น
เทสต์จะผ่านแบบไม่ได้ทดสอบอะไรเลย

`sb.mjs` · `wp.mjs` เป็นสำเนาของฝั่ง send-reminders โดยตั้งใจ — สองชุดเทสต์แยกขาดจากกัน
การแก้ของชุดหนึ่งจะได้ไม่ทำอีกชุดตกโดยไม่ตั้งใจ
